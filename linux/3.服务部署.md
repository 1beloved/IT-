## 第 3 周：服务部署（岗位实操）

**目标：理解一个服务从「装好」到「用户能访问」的完整链路，并能运维它。**

### 3.1 完整访问链路

用户访问 `http://demo.local/`，依次发生：

1. **DNS** 把域名解析成 IP（或 hosts）
2. **TCP 三次握手** 到服务器 80 端口
3. **防火墙 / 安全组** 放行
4. **监听**：Nginx 的 master 进程在 80 端口监听，worker 处理请求
5. **配置匹配**：按 `listen` + `server_name` 选 server，再按 `location` 选处理方式
6. **响应**：返回静态文件，或 `proxy_pass` 转给后端应用
7. **日志**：写入 access.log，出错写 error.log

任何一环断了都是故障点，这就是第 2 周排障表的由来。

### 3.2 安装与基础管理 Nginx

```bash
sudo apt update && sudo apt install -y nginx
sudo systemctl enable --now nginx
curl -I http://127.0.0.1          # 期望 HTTP/1.1 200 OK
nginx -v; nginx -V                # 版本与编译参数
```

|   |   |
|---|---|
|路径|说明|
|`/etc/nginx/nginx.conf`|主配置|
|`/etc/nginx/conf.d/*.conf`|子配置（通用）|
|`/etc/nginx/sites-available/`、`sites-enabled/`|Ubuntu 习惯：available 存配置，enabled 放软链接|
|`/var/www/html`|默认网站根目录|
|`/var/log/nginx/access.log`、`error.log`|日志|

### 3.3 配置示例

一个静态站 + 一个反向代理：

```nginx
server {
    listen 80;
    server_name demo.local;
    root /var/www/demo;
    index index.html;

    access_log /var/log/nginx/demo.access.log;
    error_log  /var/log/nginx/demo.error.log;

    location / {
        try_files $uri $uri/ =404;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**标准修改流程（养成肌肉记忆）**：

```bash
sudo cp -a /etc/nginx/conf.d/demo.conf /etc/nginx/conf.d/demo.conf.bak.$(date +%F)  # 1 先备份
sudo vim /etc/nginx/conf.d/demo.conf     # 2 修改
sudo nginx -t                            # 3 语法检查，必做
sudo systemctl reload nginx              # 4 平滑生效
curl -I -H 'Host: demo.local' http://127.0.0.1   # 5 验证
```

常见错误：

|   |   |
|---|---|
|现象|原因与处理|
|`bind() to 0.0.0.0:80 failed (Address already in use)`|端口被占，`ss -tulnp \| grep :80` 找出占用者|
|403 Forbidden|目录或文件权限不足（路径每一级需 `x`），或 root 下没有 index|
|404 Not Found|`root` 路径写错，或文件不存在|
|502 Bad Gateway|`proxy_pass` 的后端没启动 / 端口错|
|改了配置没生效|没 reload；或改错了被覆盖的文件，用 `nginx -T` 看生效配置|

### 3.4 把自己的程序做成服务（systemd unit）

`/etc/systemd/system/demo.service`：

```ini
[Unit]
Description=Demo App
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/demo
ExecStart=/usr/bin/python3 -m http.server 8000
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now demo
systemctl status demo; journalctl -u demo -f
```

把 `kill` 掉进程，观察 `Restart=on-failure` 自动拉起，这就是服务化的价值。

### 3.6 日志分析（Nginx 为例）

access.log 默认格式：`IP - - [时间] "请求" 状态码 字节数 "Referer" "UA"`。

```bash
# 访问量 TOP10 的 IP
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head
# 各状态码统计
awk '{print $9}' access.log | sort | uniq -c | sort -nr
# 所有 5xx 请求
awk '$9 ~ /^5/' access.log | tail
# 实时看错误
tail -f error.log
```

### 3.7 简单备份

原则：**备份没做过恢复演练，就等于没有备份**。

```bash
# 配置 + 网站数据打包
sudo tar -czf /backup/web_$(date +%F).tar.gz /etc/nginx /var/www
tar -tzf /backup/web_$(date +%F).tar.gz | head   # 验证
# 异地增量同步
rsync -avz /backup/ ops@backup-host:/data/backup/
# 保留 7 天
find /backup -name 'web_*.tar.gz' -mtime +7 -delete
```

思路：3-2-1 原则（至少 3 份、2 种介质、1 份异地）；改配置前先 `cp -a` 留底；备份任务交给 cron（第 4 周）；定期把备份解压到临时目录演练恢复。
