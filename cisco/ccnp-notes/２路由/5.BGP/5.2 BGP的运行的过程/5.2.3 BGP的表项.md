
## 一、三张表

| 表                               | 作用                        | 查看命令                  |
| ------------------------------- | ------------------------- | --------------------- |
| **邻居表**                         | 记录所有 BGP 邻居及状态            | `show ip bgp summary` |
| **BGP 表**（BGP table / 拓扑表）      | 存放收到和本地产生的所有 BGP 路由，选最优路径 | `show ip bgp`         |
| **路由表**（RIB / IP routing table） | 只放 BGP 选出的最优路由，用来转发       | `show ip route bgp`   |

注意：BGP 表和路由表是两回事。BGP 表里可以有很多条到同一前缀的路径，但只有最优的那条才有机会进路由表。

## 二、邻居表

```
Neighbor     V   AS  MsgRcvd MsgSent TblVer InQ OutQ Up/Down  State/PfxRcd
10.1.1.2     4  65002   120     118     5     0   0   01:40:21   3
```

- **V**：BGP 版本，一般是 4
- **AS**：对端 AS 号
- **TblVer**：已发给对端的 BGP 表版本号
- **InQ/OutQ**：等待处理 / 等待发送的报文数，长期不为 0 说明有堵塞
- **Up/Down**：邻居保持 Established 的时间，经常归零说明邻居在震荡
- **State/PfxRcd**：数字表示已建立并收到的前缀数；单词（Idle、Active 等）表示还没建立

## 三、BGP 表

```
   Network          Next Hop        Metric LocPrf Weight Path
*> 10.0.0.0/24      0.0.0.0              0         32768 i
*  172.16.0.0       10.1.1.2             0             0 65002 i
*>i192.168.1.0      2.2.2.2              0    100      0 i
```

**状态码（最前面几列）**

- `*`：有效路由（下一跳可达）
- `>`：最优路径，只有它会被放进路由表并通告给邻居
- `i`：从 iBGP 邻居学到
- `s`：被抑制（summary-only 或 dampening 相关）
- `d`：被惩罚（dampened）
- `h`：历史记录（history）
- `r`：RIB-failure，是最优路径但没能装进路由表（比如已有 AD 更低的路由）

**起源码（Path 最后一位）**

- `i`：通过 `network` 命令引入的 IGP 来源
- `e`：来自 EGP（历史遗留）
- `?`：incomplete，通常是 `redistribute` 引入的

**各列含义**

- **Next Hop**：下一跳；`0.0.0.0` 表示本地产生的路由
- **Metric**：即 MED，用于影响邻居 AS 的入站选路
- **LocPrf**：Local Preference，默认 100，仅在 AS 内部传递
- **Weight**：思科私有，默认本地产生 32768，学来的为 0，仅本地有效，不传递
- **Path**：AS_PATH，从近到远排列

## 四、路由表

```
B    172.16.0.0/16 [20/0] via 10.1.1.2, 01:40:21
B    192.168.1.0/24 [200/0] via 2.2.2.2, 01:30:10
```

- **eBGP 的 AD 是 20**，**iBGP 的 AD 是 200**，本地产生的（聚合等）是 200
- 括号里 `[AD/Metric]`，Metric 取 BGP 的 MED
- iBGP 学到的路由，下一跳是 BGP 下一跳（如 2.2.2.2），需要递归查路由表找到出接口，所以 IGP 必须能到达它

## 五、RIB 内部模型

协议规范里，BGP 表其实分成三部分：

```
邻居 UPDATE
   ↓ 入站策略（route-map in / prefix-list in / filter-list in）
Adj-RIB-In     ← 收到的原始路由，每个邻居一份
   ↓ 选路（best path selection）
Loc-RIB        ← 选出的最优路径（即 show ip bgp 里带 > 的）
   ↓ 与其他协议比较 AD，最优者装入 IP 路由表
   ↓ 出站策略（route-map out / prefix-list out）
Adj-RIB-Out    ← 将要通告给每个邻居的路由
   ↓
邻居
```

## 六、实际配置里最容易踩的几个点

1. **`network` 命令要求路由表里有精确匹配的路由**：`network 10.0.0.0 mask 255.255.255.0` 要生效，路由表里必须已经有 10.0.0.0/24（直连、静态或 IGP 都行）。没有的话，这条路由不会进 BGP 表。这也是 BGP 里常见的"明明配了 network 却没通告"的原因。
2. **入站策略改了要刷新**：邻居发来的原始路由默认不保存修改前的版本，所以改完入站策略要执行 `clear ip bgp x.x.x.x soft in`，利用 Route-Refresh 重新获取。如果对端不支持，可以配 `neighbor x.x.x.x soft-reconfiguration inbound`，在本地多保存一份 Adj-RIB-In（会多占内存）。出站策略改了用 `clear ip bgp x.x.x.x soft out`。
3. **有 `*` 没 `>`**：路由有效但不是最优，选路时被别的路径比下去了。去看选路 13 步，哪一步输了。
4. **没有 `*`**：下一跳不可达，大多是 iBGP 没配 `next-hop-self`，或者 IGP 没通到下一跳。
5. **有 `>` 但路由表里没有**：看有没有 `r` 标志，一般是有 AD 更低的路由（比如 OSPF 的 110 比 iBGP 的 200 低）占了位置。

## 七、常用查看命令汇总

```
show ip bgp                       ! BGP 表
show ip bgp 10.0.0.0/24           ! 某前缀的所有路径及属性详情，选路排错最常用
show ip bgp neighbors x.x.x.x advertised-routes   ! 通告给邻居的（Adj-RIB-Out）
show ip bgp neighbors x.x.x.x received-routes     ! 收到的原始路由(需 soft-reconfiguration)   neighbor 10.1.1.2 soft-reconfiguration inbound
clear ip bgp 10.1.1.2 soft in
show ip bgp neighbors x.x.x.x routes              ! 收到且通过入站策略的路由
```
