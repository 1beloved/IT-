## 2. BGP 是什么

**BGP(Border Gateway Protocol)** 是**路径矢量协议**,当前版本 BGP-4,跑在 **TCP 179** 上,负责域间路由和策略控制。

- IGP(OSPF/EIGRP/IS-IS)解决:AS 内部怎么快速到达下一跳。
- BGP 解决:AS 之间哪些前缀可达、走哪条外部路径、能不能继续通告。
- BGP 的核心价值不是算最短路,而是**策略控制**。
- 邻居建立后只发增量更新,不做周期性全量更新。

|             |                                                      |
| ----------- | ---------------------------------------------------- |
| 项目          | 说明                                                   |
| 管理距离(Cisco) | eBGP 20,iBGP 200,本地产生 200                            |
| 防环核心        | AS_PATH、iBGP 水平分割、RR 的 ORIGINATOR_ID / CLUSTER_LIST  |
| 策略核心        | Path Attribute + route-map / prefix-list / community |

**适合用 BGP**:多 ISP 出口要控制出入站、需要和运营商交换公网路由、做中转 AS、大型网络要精细控制路由传播。 **不适合**:只有单出口(静态默认路由更简单)、没有自己的策略、设备扛不住路由规模。

## 3. AS 与 ASN

**AS_PATH 的两个作用:防环**(收到的路径里有本地 AS 就拒绝)**和选路**(越短越优)。

|   |   |
|---|---|
|类型|范围|
|16-bit 公有|1 - 64495|
|16-bit 文档保留|64496 - 64511|
|16-bit 私有|64512 - 65534|
|特殊|0、23456(AS_TRANS)、65535|
|32-bit 私有|4200000000 - 4294967294|

4-byte AS 的 asdot 写法:`ASPLAIN = 高16位 × 65536 + 低16位`,例如 `1.15 = 65551`。现在主流用 ASPLAIN。

术语:BGP Speaker(运行 BGP 的路由器)、NLRI(网络层可达信息,即前缀)、Path Attribute(路径属性)。

## 4. BGP 报文(考)

报文封装在 TCP 里,先三次握手再交换 BGP 报文。公共头 19 字节(Marker 16 + Length 2 + Type 1),报文总长最大 4096 字节。


| Type | 名称            | 作用                                        |
| ---- | ------------- | ----------------------------------------- |
| 1    | OPEN          | 建立会话,协商 AS、Router ID、Hold Time、Capability |
| 2    | UPDATE        | 通告或撤销路由                                   |
| 3    | NOTIFICATION  | 报错并关闭会话                                   |
| 4    | KEEPALIVE     | 保活,只有 19 字节头                              |
| 5    | ROUTE-REFRESH | 扩展报文,请求对端重发某地址族路由                         |

**OPEN** 常见 Capability:Multiprotocol Extensions(IPv6 等)、Route Refresh、4-byte AS、Graceful Restart、Add-Path。Hold Time 双方取较小值;非 0 时至少 3 秒;0 表示不使用。

**UPDATE** 组成:Withdrawn Routes(撤销)、Path Attributes(属性)、NLRI(新通告前缀)。同一个 UPDATE 里的 NLRI 共享同一组属性,属性不同要分开发。IPv4 Unicast 直接放 NLRI,其他地址族用 MP_REACH_NLRI / MP_UNREACH_NLRI。

**NOTIFICATION** 常见原因:OPEN 错误(AS 不匹配、Hold Time 不可接受、Router ID 冲突)、Capability 不兼容、Hold Timer 超时、UPDATE 格式错误、Cease。发送后 TCP 连接关闭。

**ROUTE-REFRESH**:修改入站策略后不必重置 TCP 会话,让对端重发路由再按新策略处理。需要 OPEN 中双方协商过 Route Refresh 能力。

## 5. 邻居状态机与计时器(考)

```
Idle -> Connect -> (Active) -> OpenSent -> OpenConfirm -> Established
```

|             |                          |                            |
| ----------- | ------------------------ | -------------------------- |
| 状态          | 含义                       | 常见问题                       |
| Idle        | 初始/出错后回退,等待 Start 事件     | 邻居被 shutdown、配置缺失          |
| Connect     | 等待 TCP 连接完成              | 路由不可达、TCP 179 被阻断          |
| Active      | TCP 失败后继续主动尝试(不是「活跃」的意思) | 对端没监听、ACL、update-source 不对 |
| OpenSent    | TCP 已通,已发 OPEN,等对端 OPEN  | AS 不匹配、Capability 不兼容      |
| OpenConfirm | OPEN 通过,等 KEEPALIVE      | Keepalive 异常               |
| Established | 会话建立,可交换 UPDATE          | 正常                         |

**记忆要点**:

- 在 Idle / Connect / Active 之间反复:**TCP 层没通**(路由、ACL、邻居地址、update-source、eBGP TTL)。
- OpenSent 后断开:**OPEN 参数有问题**(AS、Router ID、Hold Time、Capability)。
- TCP MD5 认证发生在 TCP 层,不匹配时连 TCP 都建不起来,不会进入 OPEN 协商。
- Established 只代表会话成功,不代表地址族已激活,也不代表有路由或路由进了 RIB。
- 收到 NOTIFICATION、TCP 断开、Hold Timer 超时,基本都会回到 Idle。

|   |   |   |
|---|---|---|
|计时器|默认值|作用|
|Keepalive|60 秒|周期保活|
|Hold Time|180 秒|超时未收到任何报文则断开|
|ConnectRetry|120 秒|TCP 连接重试|
|Advertisement Interval|eBGP 30 秒 / iBGP 5 秒|控制更新发送间隔(平台可能不同)|

```
router bgp 65001
 timers bgp 10 30                       ! keepalive 10, hold 30
 neighbor 192.0.2.1 timers 10 30        ! 邻居级别
```

要更快检测故障,用 **BFD**,不要把 BGP 计时器调得很小。

## 6. BGP 表结构与路由处理流程(考)

```
收 UPDATE -> Adj-RIB-In -> 入站策略 -> BGP 表(候选) -> Best Path(Loc-RIB)
         -> IP RIB / FIB -> 出站策略 -> Adj-RIB-Out -> 发 UPDATE
```

|   |   |   |
|---|---|---|
|表|含义|命令|
|Adj-RIB-In|邻居发来的、策略前的原始路由|`show ip bgp neighbors X received-routes`(需 soft-reconfiguration inbound)|
|BGP 表|入站策略后的候选路径|`show ip bgp`、`show ip bgp neighbors X routes`|
|Best Path|BGP 选出的最佳路径(`>`)|`show ip bgp`|
|Adj-RIB-Out|出站策略后准备发给邻居的路由|`show ip bgp neighbors X advertised-routes`|
|IP RIB / FIB|全局路由表 / CEF|`show ip route bgp`、`show ip cef`|

**show ip bgp 标记**:`*` 有效(下一跳可达)、`>` 最佳、`i` iBGP 学来、`r` RIB-failure、`s` 被聚合抑制、`d` 被 damping 抑制、`h` 历史路径。

**软刷新**(改了策略后用,不用硬清邻居):

```
clear ip bgp 192.0.2.1 soft in     ! 重新应用入站策略(依赖 Route Refresh)
clear ip bgp 192.0.2.1 soft out    ! 重新应用出站策略并重发
router bgp 65001
 neighbor 192.0.2.1 soft-reconfiguration inbound   ! 本地保存策略前路由,吃内存
```

**排查一条路由为什么没出现,按顺序看**:邻居 Established → 是否收到 → 入站策略是否放行 → 下一跳可达/路径 valid → 是否 Best → 是否装进 RIB → 出站策略是否允许通告。

## 7. eBGP 与 iBGP(考)

|          |                   |                       |
| -------- | ----------------- | --------------------- |
| 对比       | eBGP              | iBGP                  |
| 邻居       | 不同 AS             | 相同 AS                 |
| 默认 TTL   | 1                 | 255                   |
| AD       | 20                | 200                   |
| AS_PATH  | 向外通告时加本地 AS       | 不加                    |
| Next-Hop | 通告给 eBGP 邻居时改为自己  | 默认不改                  |
| 防环       | AS_PATH 含本 AS 则拒绝 | 从 iBGP 学到的不再传给其他 iBGP |
| 建邻方式     | 通常直连接口            | 常用 Loopback           |

**通告原则**:iBGP 来的 → 只给 eBGP;eBGP 来的 → 给 iBGP 和 eBGP;本地产生的 → 都可以。并且默认只通告 Best Path,最终受出站策略控制。

**为什么有 IGP 还要 iBGP**:IGP 负责「内部怎么到达下一跳」,iBGP 负责「把外部 BGP 路由和属性(LocalPref、Community 等)在 AS 内传递」。不要把 BGP 重分发进 IGP:属性会丢失、IGP 扛不住规模、容易次优路径和黑洞。企业典型做法是边界路由器用 `default-information originate` 给内部下发默认路由。

## 8. 基础配置要点(考)

### 8.1 network 命令

BGP 的 `network` 与 IGP 完全不同:**不启用接口,而是把 RIB 中已存在的精确前缀注入 BGP**。

```
ip route 10.10.10.0 255.255.255.0 Null0     ! 没有精确路由时,用 Null0 兜底
router bgp 65001
 network 10.10.10.0 mask 255.255.255.0
```

|   |   |   |
|---|---|---|
|注入方式|Origin|说明|
|network|i|对外通告首选,要求精确匹配|
|redistribute|?|必须配 route-map / prefix-list 过滤,否则可能泄漏内部网段|
|aggregate-address|继承或聚合产生|对外减少前缀,注意黑洞|

### 8.2 eBGP 多跳与 TTL Security

```
router bgp 65001
 neighbor 2.2.2.2 remote-as 65002
 neighbor 2.2.2.2 update-source Loopback0
 neighbor 2.2.2.2 ebgp-multihop 2        ! 让报文能跨多跳
```

|   |   |   |
|---|---|---|
||ebgp-multihop|ttl-security hops N|
|目的|放宽 TTL,让邻居够得着|收紧,只接受足够近的对端|
|方向|调大本端发出的 TTL|检查收到报文 TTL >= 255 - N|
|安全性|不是安全功能|安全增强(GTSM)|

两者目的相反,同一邻居一般二选一。口诀:multihop 是「让它够得着」,ttl-security 是「只让够近的人进来」。

### 8.3 iBGP 邻居

```
router bgp 65001
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source Loopback0   ! 用 Loopback 建邻
 neighbor 2.2.2.2 next-hop-self             ! 边界路由器上常用
```

前提:双方 Loopback 互通(IGP 提供)、remote-as 一致、TCP 179 放行。

### 8.4 iBGP 水平分割与 Full Mesh

从 iBGP 邻居学到的路由,默认**不会**再通告给另一个 iBGP 邻居(iBGP 不改 AS_PATH,靠这条规则防环)。解决:

- **Full Mesh**:邻居数 `n(n-1)/2`,规模大了不现实。
- **Route Reflector**、**Confederation**(见后文)。

### 8.5 Next-Hop 与黑洞

路由有效的前提是 **Next-Hop 可达**(可递归解析,不要求直连)。

|   |   |   |
|---|---|---|
|场景|默认行为|处理|
|eBGP 路由传给 iBGP|下一跳不变|边界路由器对 iBGP 邻居配 `next-hop-self`,或让 IGP 能到原下一跳|
|iBGP 传给 iBGP|下一跳不变|保证 IGP 能到原始下一跳|
|RR 反射|通常不改|乱改会让流量被吸到 RR|

**BGP 黑洞**:控制平面有路由,数据平面却丢包。典型是 **BGP-free Core**:边界和核心外的设备有 BGP 路由,但中间的纯 IGP 路由器没有远端明细,也没有默认路由,包到那里就被丢。修复:边界下发 IGP 默认路由,或核心也运行 BGP。排查三连:`show ip bgp <prefix>`、`show ip route <next-hop>`、`show ip cef <dest> detail`。

### 8.6 BGP Synchronization(了解)

老机制:iBGP 学到的路由在通告给 eBGP 之前,IGP 里也必须有这条路由,用来防止过渡 AS 内部黑洞。现代 Cisco 设计默认 `no synchronization`,靠正确的 iBGP 设计和 Next-Hop 可达来避免黑洞。**别和 iBGP 水平分割混淆**:水平分割防 iBGP 内部成环,同步规则防 iBGP 路由误引流进黑洞。

## 9. 路径属性(考)

### 9.1 四类分类

|   |   |   |
|---|---|---|
|分类|含义|属性举例|
|Well-known Mandatory|必须识别,且每条 UPDATE 必须携带|ORIGIN、AS_PATH、NEXT_HOP|
|Well-known Discretionary|必须识别,但不一定携带|LOCAL_PREF、ATOMIC_AGGREGATE|
|Optional Transitive|可不识别,不识别也要继续传|AGGREGATOR、COMMUNITY、Extended/Large Community|
|Optional Non-transitive|可不识别,不识别就不传|MED、ORIGINATOR_ID、CLUSTER_LIST、MP_REACH/UNREACH_NLRI|

注意:**Weight 是 Cisco 本地属性,不属于标准 BGP 属性,不会通告给邻居**。eBGP/iBGP 类型、到下一跳的 IGP Metric、Router ID、邻居地址也都是本地比较条件,不在 UPDATE 里。

### 9.2 常用属性速记

|   |   |   |   |
|---|---|---|---|
|属性|方向|传递范围|作用|
|Weight|大优先|仅本机|控制单台路由器出站(本地产生默认 32768,学来的默认 0)|
|Local Preference|大优先|AS 内(iBGP)|控制整个 AS 的**出站**,默认 100|
|AS_PATH|短优先|跨 AS|防环、选路、prepend 影响入站|
|Origin|i < e < ?|跨 AS|network 为 i,redistribute 为 ?|
|MED|小优先|相邻 AS|建议邻居 AS 从哪个入口进来|
|Community|不直接选路|需 send-community|路由打标签,统一应用策略|

**AS_PATH 的 Segment**:AS_SEQUENCE(有序,最常见)、AS_SET(无序,聚合 as-set 时出现,长度按 1 计)、AS_CONFED_SEQUENCE / AS_CONFED_SET(联邦内部,对外隐藏)。

**MED 默认只在来自同一相邻 AS 的路径之间比较**。要跨 AS 比较需要 `bgp always-compare-med`。没有 MED 默认按 0,可用 `bgp bestpath med missing-as-worst` 改为最差。

**Community**:

|   |   |
|---|---|
|值|含义|
|aa:nn|自定义标记,如 65001:100|
|no-advertise|不通告给任何 BGP 邻居(最严格)|
|no-export|不通告给真正的外部 AS|
|local-AS|不出本地 AS / 本地联邦范围|
|internet|正常传播,不是「上互联网」|
|gshut|Graceful Shutdown,等价 65535:0|

```
ip bgp-community new-format
route-map SET-COMM permit 10
 set community 65001:100 additive      ! additive 否则会覆盖原有值
router bgp 65001
 neighbor 203.0.113.1 send-community    ! 忘了这条,对端收不到
```

## 10. Best Path 选路 13 步(考,必背)

先判断路径是否**有效**(下一跳可达、没被拒绝、AS_PATH 无本 AS、地址族已激活),有效的才进入比较,某一步分出胜负即停止。

|   |   |   |
|---|---|---|
|顺序|比较项|规则|
|1|Weight|最高优先(Cisco 本地)|
|2|Local Preference|最高优先|
|3|Locally Originated|本机通过 network / redistribute / aggregate 产生的优先|
|4|AS_PATH|最短优先|
|5|Origin|IGP > EGP > Incomplete|
|6|MED|最小优先(默认仅同一相邻 AS 比较)|
|7|eBGP / iBGP|eBGP > 联邦 eBGP > iBGP|
|8|IGP Metric to Next-Hop|到 BGP 下一跳的 IGP 度量最小|
|9|Multipath|满足条件且配了 maximum-paths 时装入多条路径|
|10|Oldest eBGP|最早收到的 eBGP 路径(`bgp bestpath compare-routerid` 会跳过)|
|11|Router ID|最小优先;RR 环境用 Originator ID|
|12|Cluster List|最短优先|
|13|Neighbor Address|最小优先|

**速记**:高 Weight、高 LocalPref、本地产生、短 AS_PATH、低 Origin、低 MED、eBGP、低 IGP Metric、Multipath、老 eBGP、低 RID、短 Cluster List、低邻居地址。

**关键细节**:

- 第 8 步比较的是到**下一跳地址**的 IGP 代价,不是到目标前缀。
- `>` 表示 BGP 选中,不代表一定装进 RIB。如果被更低 AD 的路由压住,会出现 `r`(RIB-failure),用 `show ip bgp rib-failure` 查。
- 下一跳不可达的路径(没有 `*`)连比较资格都没有,即使 LocalPref 再高。
- `bgp deterministic-med` 让同一相邻 AS 的 MED 比较不受接收顺序影响。

## 11. 选路调整与策略工具(考,ENARSI 重点)

BGP 调路不是改线路,而是用路径属性和策略影响 Best Path。先分清方向:

|   |   |   |   |
|---|---|---|---|
|目标|控制谁的选择|常用工具|确定性|
|控制本 AS **出站**|自己|Weight、Local Preference、IGP Metric、过滤|高|
|控制外部**入站**|别人|AS Path Prepend、MED、Community、更明细前缀|中,只能影响|

**原则**:

- 能在本 AS 内解决的,优先用 **Local Preference**(iBGP 内传递,全 AS 一致)。
- 只影响单台设备用 **Weight**(权重最先比较,会盖过 LocalPref)。
- 影响入站:先看对端 ISP 是否支持 Community,其次 MED(仅同一相邻 AS 有效),再其次 AS Path Prepend。
- 更明细前缀吸引力最强(最长匹配优先于属性),但会增加公网路由规模。
- 策略方向:`in` 影响本地选路,`out` 影响对端看到什么。

### 11.1 常用配置

```
! 出站:主用 ISP-A,备用 ISP-B
route-map ISP-A-IN permit 10
 set local-preference 200
route-map ISP-B-IN permit 10
 set local-preference 100
router bgp 65001
 neighbor 192.0.2.1 route-map ISP-A-IN in
 neighbor 198.51.100.1 route-map ISP-B-IN in

! 入站:让 ISP-B 作备份,拉长 AS_PATH
route-map ISP-B-OUT permit 10
 match ip address prefix-list PUBLIC-PREFIX
 set as-path prepend 65001 65001 65001
route-map ISP-B-OUT permit 100
router bgp 65001
 neighbor 198.51.100.1 route-map ISP-B-OUT out

! MED:同一 ISP 的两个入口,偏好 R1
route-map TO-ISP-R1 permit 10
 set metric 50

! Weight:仅本机
router bgp 65001
 neighbor 192.0.2.1 weight 500
```

修改策略后要 `clear ip bgp <neighbor> soft in/out`。

### 11.2 Route-map 行为

|   |   |
|---|---|
|规则|说明|
|按序号从小到大匹配|命中后通常不再往下|
|permit + match 成功|放行并执行 set|
|deny + match 成功|拒绝,不执行 set|
|没有 match|匹配所有路由|
|没有任何序号命中|**隐式 deny**|
|不同类型的 match|AND;同一类型里的多个对象|

**经典坑**:route-map 只写了一条带 match 的 permit,其余路由全被隐式 deny,邻居路由大量消失。解决:末尾加兜底 `route-map NAME permit 100`。

> 与 PBR 对比:BGP / 重分发里的隐式 deny 是真的拒绝这条路由;PBR 里的隐式 deny 是回到正常路由表转发。

### 11.3 Prefix-list 的 ge / le

|   |   |
|---|---|
|写法|含义|
|`permit 10.0.0.0/8`|只匹配 10.0.0.0/8 本身|
|`permit 10.0.0.0/8 le 24`|/8 到 /24,含 /8|
|`permit 10.0.0.0/8 ge 16`|/16 到 /32|
|`permit 10.0.0.0/8 ge 16 le 24`|/16 到 /24|
|`permit 0.0.0.0/0`|只匹配默认路由|
|`permit 0.0.0.0/0 le 32`|所有 IPv4 前缀|

Prefix-list 也有隐式 deny。拒绝默认路由、放行其余:

```
ip prefix-list NO-DEFAULT deny 0.0.0.0/0
ip prefix-list NO-DEFAULT permit 0.0.0.0/0 le 32
router bgp 65001
 neighbor 192.0.2.1 prefix-list NO-DEFAULT in
```

### 11.4 AS-path ACL(正则)

|   |   |
|---|---|
|符号|含义|
|`_`|边界(空格、开头、结尾等)|
|`^` / `$`|开头 / 结尾|
|`.` `*` `+`|任意字符 / 0 次或多次 / 1 次或多次|

|   |   |
|---|---|
|需求|正则|
|本 AS 本地产生(AS_PATH 为空)|`^$`|
|起源于 AS 65010|`_65010$`|
|经过 AS 65010|`_65010_`|
|直接来自 65010 且由它起源|`^65010$`|
|以 65010 开头|`^65010_`|

```
ip as-path access-list 10 permit _65010$
route-map MATCH-AS permit 10
 match as-path 10
 set local-preference 150
! 或直接过滤:neighbor X filter-list 10 in
```

验证:`show ip bgp regexp _65010$`。

### 11.5 其他策略工具

`community-list`(匹配 Community)、`filter-list`(调用 AS-path ACL)、`distribute-list`(传统,BGP 里不是首选)、`maximum-prefix`(限制邻居前缀数)。

### 11.6 实验结论(资料 Lab 6)

拓扑:企业 AS 65001,R1/R2 分别接 ISP1/ISP2,R3 是内部观察点,R1/R2/R3 用 Loopback 建 iBGP Full Mesh,R1/R2 对 iBGP 邻居配 `next-hop-self`。

- 默认 R3 访问 8.8.8.8 多半选 R1(前面属性相同,最终比到 Router ID 更小)。
- **LocalPref**:R2 入站设 200 → 全 AS 出站改走 R2/ISP2。
- **Weight**:只在 R3 上设 500 → 仅 R3 改走 R2,别的设备不变。
- **Prepend**:R1 对 ISP1 出站拉长 AS_PATH → 外部进入企业改走 ISP2。
- 两个入口来自不同相邻 AS(65010 / 65020),MED 默认不比较,所以不用 MED 演示。

## 12. BGP Multipath(考)

BGP 默认只选一条 Best Path。Multipath 把多条**等价**路径同时装进 IP RIB 做负载分担,Best Path 仍然只有一条(会标 `>`,其余参与者标 `m`)。

```
router bgp 65001
 maximum-paths 2          ! eBGP 等价路径数
 maximum-paths ibgp 2     ! iBGP 等价路径数
```

**等价条件**:Weight、Local Preference、AS_PATH 长度(默认内容也要一致)、Origin、MED、来源类型、到下一跳的 IGP Metric 都相同。若两条路径的 AS_PATH 长度相同但内容不同,可用 `bgp bestpath as-path multipath-relax`(平台支持时)放宽。

排查只有一条路径时:先比较上述属性是否一致,再看是否配置了 maximum-paths。

**主备与负载设计速查**:

|   |   |
|---|---|
|需求|做法|
|出站主走 ISP-A|ISP-A 入站 LocalPref 更高|
|入站主走 ISP-A|ISP-B 方向出站做 Prepend 或低优先级 Community|
|按业务分流|按目的前缀设不同 LocalPref|
|两条 eBGP 等价负载|满足条件 + maximum-paths|
|某出口只做备份|只从备用 ISP 收默认路由,或降低 LocalPref|

## 13. Route Reflector 与 Confederation(考)

### 13.1 Route Reflector

解决 iBGP Full Mesh 的规模问题:Client 只需要和 RR 建邻。

|   |   |
|---|---|
|角色|含义|
|RR|路由反射器|
|Client|RR 的客户端,不需要知道自己是 Client|
|Non-client|普通 iBGP 邻居|
|Cluster / Cluster ID|RR 加其 Client 组成的簇及其标识|

**反射规则**:

|   |   |
|---|---|
|路由来源|RR 怎么发|
|从 Client 学到|反射给其他 Client、Non-client、eBGP|
|从 Non-client 学到|反射给 Client、eBGP,**不反射给其他 Non-client**|
|从 eBGP 学到|发给 Client、Non-client、eBGP|

**防环属性**:

- `ORIGINATOR_ID`:最初发起该路由的 iBGP 路由器 RID,收到的路由里是自己 → 丢弃。
- `CLUSTER_LIST`:路由经过的 Cluster ID 列表,RR 发现含本地 Cluster ID → 丢弃。

```
router bgp 65001
 bgp cluster-id 10.10.10.10                         ! 未配时默认用本机 Router ID
 neighbor 1.1.1.1 remote-as 65001
 neighbor 1.1.1.1 update-source Loopback0
 neighbor 1.1.1.1 route-reflector-client
```

**设计要点**:

- RR 解决的是控制平面扩展,不一定在数据转发路径上;RR 随意改 Next-Hop 会把流量吸到自己身上。
- 边界路由器 Loopback 必须在 IGP 中可达。
- Client 双归属到两个 RR;同一簇内的双 RR 通常配相同 Cluster ID。
- **路径隐藏**:RR 默认只反射自己的 Best Path,Client 看不到备用路径,可能选到离自己远的出口。缓解:RR 放在拓扑中心、分区域部署 RR、IGP Metric 设计合理、Add-Path、BGP PIC。

**RR 不反射路由时排查**:邻居没配 `route-reflector-client`;路由来自 Non-client;ORIGINATOR_ID / CLUSTER_LIST 命中防环;该路径不是 RR 的 Best Path;出站策略过滤。

查看:在**接收方**用 `show ip bgp <prefix>` 看 `Originator` 和 `Cluster list`(RR 本机看 Client 直接发来的路由通常看不到)。

### 13.2 Confederation

把一个大 AS 拆成多个 Sub-AS,对外仍表现为一个 AS。

```
router bgp 65001                       ! 进程用 Sub-AS 号
 bgp confederation identifier 65000    ! 对外统一 AS
 bgp confederation peers 65002         ! 其他 Sub-AS
```

- 内部 Sub-AS 之间类似 eBGP;AS_PATH 里的联邦段对外隐藏。
- 排障比 RR 复杂,企业和运营商里 RR 更常见。
- 实验注意:跨 Sub-AS 时同样可能要 `next-hop-self`,否则外部前缀保留原始下一跳,BGP 表里能看到但 ping 不通。

## 14. 聚合、条件通告、默认路由(考)

### 14.1 聚合

```
router bgp 65001
 aggregate-address 10.10.0.0 255.255.254.0 summary-only as-set
```

|   |   |
|---|---|
|参数|含义|
|summary-only|只通告聚合,抑制明细(明细在 BGP 表里标 `s`)|
|as-set|在聚合路径中保留明细涉及的 AS(AS_SET)|
|attribute-map|设置聚合路由的属性|
|suppress-map|控制抑制哪些明细|
|advertise-map|控制满足条件时才产生聚合|

- 普通 `aggregate-address` 不一定抑制明细。
- `aggregate-address` 根据 BGP 表里的明细产生聚合;用 `network` 注入聚合前缀则本地 RIB 必须有精确路由(常用 Null0 静态兜底)。
- 聚合过大可能产生黑洞:汇总存在,但部分明细实际不可达。
- **ATOMIC_AGGREGATE** 标记聚合时可能丢失明细路径信息;**AGGREGATOR** 记录产生聚合的 AS 和 Router ID。两者都不直接参与选路。

### 14.2 条件通告

根据某些路由是否存在,决定是否通告另一批路由:

- `exist-map`:条件路由存在时才通告 advertise-map 匹配的路由。
- `non-exist-map`:条件路由**不存在**时才通告。
- 判断依据是 BGP 表中的路由,不是 ping 探测。

```
router bgp 65001
 neighbor 10.0.12.2 advertise-map ADV non-exist-map CHK
```

### 14.3 向邻居下发默认路由

- `neighbor X default-originate`:对该邻居生成默认路由(不要求本地已有)。
- `network 0.0.0.0`:本地 RIB 必须有默认路由。配合 track 的静态默认路由,上游消失时 BGP 默认路由也会撤回。
- `redistribute static`:要配过滤。
- 双出口环境里默认路由同样受 LocalPref、MED、Prepend 影响;不要把客户来的默认路由传给其他客户或上游。

## 15. 稳定性与安全特性(部分考,标「扩」的了解即可)

|   |   |
|---|---|
|特性|作用与要点|
|**Peer Group / Template**|多个邻居共用策略,减少重复配置|
|**认证**|TCP MD5(`neighbor X password ...`)或 TCP-AO;不匹配时 TCP 就建不起来;排查:密码一致、隐藏空格、TCP 179 是否被挡|
|**BFD**|毫秒/秒级故障检测,比调小 BGP 计时器更合适;`bfd interval 50 min_rx 50 multiplier 3`|
|**maximum-prefix**|限制邻居前缀数,防异常压垮设备;`warning-only` 只告警;不加时超限可能关闭邻居|
|**Graceful Restart**|控制平面重启时邻居暂时保留旧路由(Stale Route),重启完成发 End-of-RIB;若转发平面也不可用会造成黑洞|
|**Route Flap Damping**|路由频繁震荡时累加惩罚值;超 Suppress Limit 被抑制,衰减到 Reuse Limit 以下恢复;公网边界谨慎使用,路由带 `d` / `h` 标记时要考虑|
|**remove-private-as**|对外通告时移除私有 AS,防私有 AS 泄漏到公网|
|**local-as**|迁移场景使用,会改变对端看到的 AS,谨慎|
|Graceful Shutdown|维护前先降低路径吸引力(LocalPref 或 gshut Community),等流量迁走再关邻居|
|扩:Add-Path|对同一前缀通告多条路径,缓解 RR 路径隐藏,代价是内存和 UPDATE 增加|
|扩:ORF|接收方把入站前缀过滤条件推给对端,让对端少发路由|
|扩:BGP PIC|提前准备备份路径,故障时 FIB 快速切换,不是新属性,依赖平台|
|扩:RPKI / ROV|只验证起源 AS 是否有权起源该前缀(Valid / Invalid / NotFound),不验证完整 AS_PATH|
|扩:RTBH|DDoS 应急,通告目标 /32 并打黑洞 Community 指向 Null0,必须严格限制触发源|

**公网边界过滤基线**:只收应该收的,只发自己有权发的。

- 入站:prefix-list、AS-path ACL、maximum-prefix、过滤 Bogon、明确是否接受默认路由、RPKI。
- 出站:只通告本 AS 合法前缀、检查 AS_PATH 防止把上游路由转给其他上游、remove-private-as、Community / Prepend。

## 16. MP-BGP 与 IPv6 BGP(考)

**BGP4+** 就是用 MP-BGP 承载 IPv6 Unicast,邻居关系、路径属性、选路规则不变。

|   |   |   |
|---|---|---|
|对比|IPv4 Unicast|IPv6 Unicast|
|地址族|默认 IPv4|`address-family ipv6 unicast`|
|前缀承载|UPDATE 传统 NLRI|`MP_REACH_NLRI`(Type 14)|
|撤销|Withdrawn Routes 字段|`MP_UNREACH_NLRI`(Type 15)|
|下一跳|NEXT_HOP 属性|MP_REACH_NLRI 里的 IPv6 Next Hop|
|查看命令|`show ip bgp`|`show bgp ipv6 unicast`|

**OPEN 里协商 Multiprotocol Capability**(AFI / SAFI):

|   |   |   |
|---|---|---|
|AFI|SAFI|地址族|
|1|1|IPv4 Unicast|
|2|1|IPv6 Unicast|
|1|128|VPNv4(了解)|
|25|70|L2VPN EVPN(了解)|

```
ipv6 unicast-routing
router bgp 65001
 neighbor 2001:db8:12::2 remote-as 65002
 address-family ipv6 unicast
  neighbor 2001:db8:12::2 activate      ! 不 activate 就没有 IPv6 路由
  network 2001:db8:1::/48               ! 同样要求 IPv6 RIB 里有精确前缀
 exit-address-family
```

- IPv6 iBGP 同样常用 Loopback + `update-source`,必要时 `next-hop-self`。
- 也可以用 **IPv4 会话承载 IPv6 NLRI**:邻居地址写 IPv4,在 `address-family ipv6 unicast` 下 activate,并保证 IPv6 下一跳正确(例如用 route-map `set ipv6 next-hop global ...`)。
- 一个 TCP 会话可协商多个地址族,但每个地址族都要**单独 activate** 和配策略。
- 邻居 Established 不代表某地址族已协商成功。
- 抓包重点:OPEN 里的 Multiprotocol Capability,UPDATE 里的 MP_REACH_NLRI / MP_UNREACH_NLRI。
- IPv6 路由收到了但不是 valid:先查 IPv6 Next Hop 能否递归到本地 IPv6 路由表。

## 17. 命令速查与排障

### 17.1 命令

|   |   |
|---|---|
|目的|命令|
|邻居|`show ip bgp summary`、`show ip bgp neighbors`、`show bgp ipv6 unicast summary`|
|BGP 表|`show ip bgp`、`show ip bgp <prefix>`、`show ip bgp regexp _65010$`、`show ip bgp community 65001:100`、`show ip bgp rib-failure`|
|收发|`... neighbors X received-routes / routes / advertised-routes`|
|策略|`show route-map`、`show ip prefix-list`、`show ip as-path-access-list`、`show ip community-list`|
|路由与转发|`show ip route bgp`、`show ipv6 route bgp`、`show ip cef <ip> detail`|
|软刷新|`clear ip bgp X soft in/out`、`clear bgp ipv6 unicast X soft in`|
|状态机观察|`debug ip bgp`(慎用)、`show tcp brief`,结束后 `undebug all`|

### 17.2 排障流程

1. 邻居 Established 吗?否 → 查 IP 可达、TCP 179、AS 号、update-source、eBGP TTL / multihop、认证。
2. 地址族激活了吗?否 → `address-family` 下 `neighbor activate`。
3. 有收发前缀吗?否 → 查 `network` 精确路由、prefix-list / route-map、出站策略。
4. 路由有效吗(有 `*`)?否 → 查 Next-Hop 可达、AS_PATH、本地策略。
5. 进了 RIB 吗?否 → 查 AD、更优路由、`rib-failure`。
6. 都有了还不通 → 查 CEF、回程路由、数据平面。

### 17.3 常见故障表

|   |   |
|---|---|
|现象|常见原因|
|邻居 Idle|邻居未配置、被 shutdown、update-source 不对|
|邻居 Active|TCP 179 不通、路由不可达、ACL|
|OpenSent 后断开|AS 不匹配、Router ID 冲突、Capability 不兼容|
|Established 但无路由|地址族未激活、network 前缀不在 RIB、策略过滤|
|有路由但无 `*`|Next-Hop 不可达,iBGP 缺 next-hop-self|
|有 `>` 但不进路由表|AD 输给其他路由、RIB-failure|
|iBGP 不传路由|水平分割、无 RR、无 Full Mesh|
|RR 不反射|没配 client、防环命中、策略过滤|
|选路不符预期|策略没匹配到前缀、方向写反、没 soft in、Weight 盖过 LocalPref|
|Community 不生效|没 send-community,或匹配列表错误|
|Prepend 后入站不变|对端先比 LocalPref;运营商可能重写;对端看到更明细前缀|
|聚合后黑洞|聚合过大,缺少明细或 Null0 设计错误|

## 18. 高频易错点与自测

### 易错点

1. BGP `network` 不启用接口,要求 RIB 里有**精确**前缀。
2. iBGP 默认不改 Next-Hop,边界路由器要 `next-hop-self`。
3. 从 iBGP 学到的路由不传给其他 iBGP(RR 是例外)。
4. Weight 是 Cisco 本地、只在本机、最先比较;LocalPref 控制出站;Prepend / MED / Community 影响入站。
5. MED 默认只比较同一相邻 AS 的路径。
6. Community 要 `send-community`;`set community` 保留原值要 `additive`。
7. route-map 末尾有隐式 deny,别忘了兜底 `permit`。
8. `>` 只是 BGP 选中,不等于进了 RIB(`r` = RIB-failure)。
9. `passive-interface` 对 OSPF / EIGRP 不发 Hello,对 RIP 只停发更新;和 BGP 无关,BGP 邻居用 `neighbor` 命令定义。
10. Established 不代表有路由。
11. 同步规则(Synchronization)与水平分割别混淆,现代设计默认关闭同步。
12. `ebgp-multihop` 与 `ttl-security` 目的相反,一般二选一。

### 自测

1. BGP 邻居卡在 Active,第一步查什么?(TCP 层:路由、ACL、邻居地址、update-source)
2. R3 从 R2 学到 iBGP 路由,为什么不传给 R4?怎么解决?
3. 为什么 R3 的 BGP 表里有前缀却没有 `*`?
4. 想让整个 AS 出站走 ISP-A,用什么?想只影响一台路由器,用什么?
5. 想让别的 AS 少从 ISP-B 进来,有哪些办法,各自的限制是什么?
6. `network 10.10.10.0 mask 255.255.255.0` 配了却没通告,原因?
7. RR 为什么会有路径隐藏?列举缓解方法。
8. IPv6 邻居 Established 但没有 IPv6 路由,查哪里?

## 19. 一句话总结

> BGP 用 TCP 179 建邻居,用 UPDATE 带着前缀和路径属性传递路由;先看路径是否有效(下一跳可达),再按 Weight → LocalPref → 本地产生 → AS_PATH → Origin → MED → eBGP/iBGP → IGP Metric 的顺序选出 Best Path;出站用 LocalPref,入站靠 Prepend / MED / Community;iBGP 靠 RR 或 Full Mesh 传递;排障按「邻居 → 地址族 → 前缀 → 有效性 → RIB → 转发」逐层看。
