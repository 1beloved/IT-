
# BGP 选路调整

> BGP 调路不是直接改“线路”，而是**通过路径属性和策略工具影响 Best Path 选择**。做实验前，先分清**方向**和**工具**。

## 一、先分方向

| 目标                  | 控制谁的选择             | 常用工具                                        |
| ------------------- | ------------------ | ------------------------------------------- |
| **控制出站**（本 AS 怎么出去） | 本 AS 自己            | Weight、**Local Preference**、IGP Metric、策略过滤 |
| **控制入站**（别人怎么进来）    | **其他 AS**，自己只能“影响” | AS Path Prepend、MED、Community、更明细前缀         |

策略方向：

|方向|处理时机|主要作用|
|---|---|---|
|`in`|路由从邻居进来时|影响**本地选路**|
|`out`|路由发给邻居前|影响**对端看到什么**|

## 二、工具总览

|调整目标|工具|配置位置|效果|
|---|---|---|---|
|控制本路由器出站|**Weight**|`neighbor ... weight`，或入站 route-map `set weight`|**只影响本设备**|
|控制本 AS 出站|**Local Preference**|入站 route-map `set local-preference`|在本 AS 内传递，**确定性高**|
|影响对端进入本 AS|**MED**|出站 route-map `set metric`|主要影响**相邻 AS**，同一 AS 多入口时更常用|
|降低某条入站路径吸引力|**AS Path Prepend**|出站 route-map `set as-path prepend`|通用，但**只能影响外部选择**|
|交给上游执行策略|**Community**|出站 route-map `set community`，并配置 `send-community`|**依赖对端约定**|
|过滤前缀|Prefix-list / Route-map|`neighbor ... prefix-list` 或 `route-map`|控制收哪些、发哪些|
|匹配路径经过的 AS|AS-path ACL / Filter-list|`match as-path` 或 `neighbor ... filter-list`|常用于来源过滤和路径控制|

## 三、调路方法论

1. **能在本 AS 内解决的，优先用 Local Preference。**
2. 只影响单台路由器时，用 **Weight**。
3. 想让对端从某个入口进入：先看对端是否支持 **Community**，其次考虑 **MED** 或 **AS Path Prepend**。
4. **MED 对不同 ISP 通常不稳定**，因为默认只在同一相邻 AS 内比较。
5. **Prepend 只是“降低吸引力”**，不能强制远端一定不走这条路。
6. **更明细前缀**通常比任何 BGP 属性都更有吸引力，但会**增加公网路由规模**，必须谨慎。

## 四、出站路径控制（Local Preference）

控制权在本 AS，**结果可预测**。

### 场景：主备出口

企业 AS 65001 有两个出口：正常时全部走 **ISP-A**，ISP-A 故障后走 **ISP-B**。

```
ip prefix-list DEFAULT-ONLY permit 0.0.0.0/0

route-map ISP-A-IN permit 10
 match ip address prefix-list DEFAULT-ONLY
 set local-preference 200
route-map ISP-A-IN permit 100

route-map ISP-B-IN permit 10
 match ip address prefix-list DEFAULT-ONLY
 set local-preference 100
route-map ISP-B-IN permit 100

router bgp 65001
 neighbor 192.0.2.1 route-map ISP-A-IN in
 neighbor 198.51.100.1 route-map ISP-B-IN in
```

|出口|LocalPref|状态|
|---|---|---|
|ISP-A|**200**|主用|
|ISP-B|100|备用|

**注意**：末尾的 `permit 100` 空条目**不能省**。route-map 末尾有隐式 deny，不加会把其他路由全部丢掉。

### 场景：按前缀分流

对不同目的前缀设置不同 LocalPref，让 A、B 各走各的：

```
ip prefix-list CLOUD-A permit 10.10.0.0/16 le 24
ip prefix-list CLOUD-B permit 10.20.0.0/16 le 24

route-map ISP-A-IN permit 10
 match ip address prefix-list CLOUD-A
 set local-preference 200
route-map ISP-A-IN permit 20
 match ip address prefix-list CLOUD-B
 set local-preference 100
route-map ISP-A-IN permit 100

route-map ISP-B-IN permit 10
 match ip address prefix-list CLOUD-A
 set local-preference 100
route-map ISP-B-IN permit 20
 match ip address prefix-list CLOUD-B
 set local-preference 200
route-map ISP-B-IN permit 100
```

## 五、入站路径控制

控制权**不完全在自己**，最终由外部网络按它们自己的策略选路。

|工具|适用场景|优点|限制|强度|
|---|---|---|---|---|
|**AS Path Prepend**|多 ISP 入站主备|通用，几乎所有 BGP 都支持|只是影响，不是强制|中|
|**MED**|同一个上游 AS 多链路|语义清晰，按入口建议对方|**不同 AS 默认通常不比较**|中|
|**Community**|ISP 支持客户控制策略|可让 ISP 设置 LocalPref、黑洞、地域传播|**依赖 ISP 文档**|高|
|**更多明细前缀**|精确吸引流量|效果强|增加路由规模，公网可能受**最小前缀长度**限制|强|

### AS Path Prepend：让 ISP-B 作为入站备用

```
ip prefix-list PUBLIC-PREFIX permit 203.0.113.0/24

route-map ISP-B-OUT permit 10
 match ip address prefix-list PUBLIC-PREFIX
 set as-path prepend 65001 65001 65001
route-map ISP-B-OUT permit 100

router bgp 65001
 neighbor 198.51.100.1 route-map ISP-B-OUT out
```

### MED：同一个 ISP（AS 65010）两个入口，希望对方优先从 R1 进入

```
route-map TO-ISP-R1 permit 10
 set metric 50
route-map TO-ISP-R2 permit 10
 set metric 200

router bgp 65001
 neighbor 192.0.2.1 route-map TO-ISP-R1 out
 neighbor 192.0.2.5 route-map TO-ISP-R2 out
```

**MED 越小越优**；这里两条链路去往**同一个相邻 AS**，MED 才会被比较。

### Community：假设 ISP 约定 `65010:80` 表示降低 LocalPref

```
route-map ISP-B-OUT permit 10
 match ip address prefix-list PUBLIC-PREFIX
 set community 65010:80 additive

router bgp 65001
 neighbor 198.51.100.1 send-community
 neighbor 198.51.100.1 route-map ISP-B-OUT out
```

**使用前必须查 ISP 的 BGP Community 文档**，不同运营商含义不同。示例中的 `65010:80` 只是假设值。

## 六、易错点速览

- 控制出站用 **in** 方向（Weight、LocalPref），影响入站用 **out** 方向（Prepend、MED、Community）。
- **Weight 只在本机有效**，不会通告给任何邻居。
- **MED 默认只比较同一相邻 AS** 的路径。
- **Prepend 用自己的 AS 号重复添加**，不要伪造别人的 AS。
- Community 要同时做到：**set community**、**send-community**、**对端约定了含义**，缺一不可。
- route-map 末尾要留 **permit 空条目**，否则其他路由被隐式 deny。

## 七、补充：配置后让策略生效

改完入站 / 出站策略后，已有路由不会自动重新处理，需要软重置：

```
clear ip bgp <neighbor> soft in
clear ip bgp <neighbor> soft out
```

**soft 方式不会断邻居**，比硬重置安全。验证用 `show ip bgp <prefix>`，查看 LocPrf、Metric、Path 是否按预期变化。
