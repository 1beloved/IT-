## 阶段 1：配接口

```
! ===== R1 =====
interface Loopback0
 ip address 1.1.1.1 255.255.255.255
interface Ethernet0/1
 description TO-ISP1
 ip address 100.0.0.1 255.255.255.0
 no shutdown
interface Ethernet0/0
 description TO-R3
 ip address 10.1.13.1 255.255.255.0
 no shutdown

! ===== R2 =====
interface Loopback0
 ip address 2.2.2.2 255.255.255.255
interface Ethernet0/1
 description TO-ISP2
 ip address 200.0.0.1 255.255.255.0
 no shutdown
interface Ethernet0/0
 description TO-R3
 ip address 10.1.23.2 255.255.255.0
 no shutdown

! ===== R3 =====
interface Loopback0
 ip address 3.3.3.3 255.255.255.255
interface Ethernet0/1
 description TO-R1
 ip address 10.1.13.3 255.255.255.0
 no shutdown
interface Ethernet0/2
 description TO-R2
 ip address 10.1.23.3 255.255.255.0
 no shutdown

! ===== ISP1 =====
interface Ethernet0/0
 description TO-R1
 ip address 100.0.0.254 255.255.255.0
 no shutdown
interface Ethernet0/1
 description TO-CORE
 ip address 10.0.100.1 255.255.255.0
 no shutdown

! ===== ISP2 =====
interface Ethernet0/0
 description TO-R2
 ip address 200.0.0.254 255.255.255.0
 no shutdown
interface Ethernet0/1
 description TO-CORE
 ip address 10.0.200.1 255.255.255.0
 no shutdown

! ===== Core =====
interface Ethernet0/1
 description TO-ISP1
 ip address 10.0.100.254 255.255.255.0
 no shutdown
interface Ethernet0/2
 description TO-ISP2
 ip address 10.0.200.254 255.255.255.0
 no shutdown
interface Loopback0
 ip address 8.8.8.8 255.255.255.255
```

网络发生了什么：

- `ip address` + `no shutdown`：接口变成 up/up，路由表里出现 `C`（直连）和 `L`（本机）路由。
- 此时没有任何路由协议，每台设备只认识自己的直连网段。比如 R3 `ping 1.1.1.1` 不通，因为 R3 没有这条路由。
- Loopback0 永远 up。后面的 iBGP 会话地址和被发布的前缀都依赖它。

验证：`show ip interface brief`，以及直连邻居互 ping。

## 阶段 2：企业内部 OSPF

```
! ===== R1 =====
interface Ethernet0/0
 ip ospf network point-to-point
router ospf 1
 router-id 1.1.1.1
 passive-interface default
 no passive-interface Ethernet0/0
 network 1.1.1.1 0.0.0.0 area 0
 network 10.1.13.0 0.0.0.255 area 0

! ===== R2 =====
interface Ethernet0/0
 ip ospf network point-to-point
router ospf 1
 router-id 2.2.2.2
 passive-interface default
 no passive-interface Ethernet0/0
 network 2.2.2.2 0.0.0.0 area 0
 network 10.1.23.0 0.0.0.255 area 0

! ===== R3 =====
interface Ethernet0/1
 ip ospf network point-to-point
interface Ethernet0/2
 ip ospf network point-to-point
router ospf 1
 router-id 3.3.3.3
 passive-interface default
 no passive-interface Ethernet0/1
 no passive-interface Ethernet0/2
 network 3.3.3.3 0.0.0.0 area 0
 network 10.1.13.0 0.0.0.255 area 0
 network 10.1.23.0 0.0.0.255 area 0
```

网络发生了什么：

- `ip ospf network point-to-point`：以太网口默认是广播类型，会选 DR/BDR。改成点到点后邻居直接进入 FULL，省掉选举。
- `passive-interface default` 加 `no passive-interface ...`：默认所有接口都不发 Hello，只在面向企业内部的接口放开。R1 的 E0/1、R2 的 E0/1 面向 ISP，不会向 ISP 发 OSPF，也不会和它们建邻居。
- `network ... area 0`：把 Loopback /32 和内部链路网段宣告进 area 0。passive 接口仍会被宣告，只是不发 Hello。
- 结果：R1–R3、R2–R3 两对邻居变成 FULL，三台路由器 LSDB 同步。R1 的路由表里出现 `O 2.2.2.2/32`（下一跳 R3）、`O 3.3.3.3/32`、`O 10.1.23.0/24`。
- R1 和 R2 没有直连，互访要经过 R3。R3 到 1.1.1.1 和 2.2.2.2 的 OSPF cost 相同，后面选路时会用到。
- OSPF 里没有 ISP 侧网段（100.0.0.0/24 等），这就是后面 `next-hop-self` 必不可少的原因。

验证：`show ip ospf neighbor`、`show ip route 2.2.2.2`、`R3# ping 1.1.1.1 source Loopback0`。

## 阶段 3：iBGP 全互联（只建会话，还没有前缀）

```
! ===== R1 =====
router bgp 65001
 bgp router-id 1.1.1.1
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source Loopback0
 neighbor 2.2.2.2 next-hop-self
 neighbor 3.3.3.3 remote-as 65001
 neighbor 3.3.3.3 update-source Loopback0
 neighbor 3.3.3.3 next-hop-self

! ===== R2 =====
router bgp 65001
 bgp router-id 2.2.2.2
 neighbor 1.1.1.1 remote-as 65001
 neighbor 1.1.1.1 update-source Loopback0
 neighbor 1.1.1.1 next-hop-self
 neighbor 3.3.3.3 remote-as 65001
 neighbor 3.3.3.3 update-source Loopback0
 neighbor 3.3.3.3 next-hop-self

! ===== R3 =====
router bgp 65001
 bgp router-id 3.3.3.3
 neighbor 1.1.1.1 remote-as 65001
 neighbor 1.1.1.1 update-source Loopback0
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source Loopback0
```

网络发生了什么：

- `router bgp 65001` 加 `bgp router-id`：启动 BGP 进程并固定 Router ID。选路最后一步比的就是它。
- `neighbor x remote-as 65001`：对端 AS 和本地相同，所以是 iBGP 邻居。
- `update-source Loopback0`：TCP 179 会话的源地址改用 Lo0。因为 OSPF 保证了 Lo0 互通，且单条物理链路断了还有另一条路，会话不会断。iBGP 默认 TTL 是 255，不需要 multihop。
- `next-hop-self`：现在还没有外部路由，看不出效果，阶段 5 才会起作用。
- 会话是双向配置的：只配一端时状态停在 Idle/Active，两端都配好才变成 Established。
- 结果：R1–R2、R1–R3、R2–R3 三个 iBGP 会话 Established。`show ip bgp summary` 里 PfxRcd 都是 0，BGP 表是空的。

## 阶段 4：eBGP 会话（仍然没有前缀）

```
! ===== R1 =====
router bgp 65001
 neighbor 100.0.0.254 remote-as 65010

! ===== R2 =====
router bgp 65001
 neighbor 200.0.0.254 remote-as 65020

! ===== ISP1 =====
router bgp 65010
 bgp router-id 11.11.11.11
 neighbor 100.0.0.1 remote-as 65001
 neighbor 10.0.100.254 remote-as 65000

! ===== ISP2 =====
router bgp 65020
 bgp router-id 22.22.22.22
 neighbor 200.0.0.1 remote-as 65001
 neighbor 10.0.200.254 remote-as 65000

! ===== Core =====
router bgp 65000
 bgp router-id 8.8.8.8
 neighbor 10.0.100.1 remote-as 65010
 neighbor 10.0.200.1 remote-as 65020
```

网络发生了什么：

- 对端 AS 不同，所以是 eBGP。邻居地址用直连接口地址，eBGP 默认 TTL 为 1，只能和直连邻居建立会话。
- 四条 eBGP 会话 Established：R1–ISP1、R2–ISP2、ISP1–Core、ISP2–Core。
- 此时全网所有 BGP 会话都已就绪，但没人发布前缀，BGP 表仍是空的。

验证：`show ip bgp summary`（R1、R2、R3、ISP1、ISP2、Core 都看一遍）。

## 阶段 5：发布前缀（BGP 表第一次有内容）

```
! ===== Core =====
router bgp 65000
 network 8.8.8.8 mask 255.255.255.255

! ===== R3 =====
router bgp 65001
 network 3.3.3.3 mask 255.255.255.255
```

`network` 要求路由表里有一条精确匹配的路由才会发布。这里两个 Loopback 都是直连路由，满足条件。

8.8.8.8 的传播过程：

1. Core 把 8.8.8.8/32 放进 BGP 表，发给 ISP1 和 ISP2，AS_PATH 是 `65000`。
2. ISP1 加上自己的 AS 后发给 R1，AS_PATH 是 `65010 65000`，下一跳 100.0.0.254。ISP2 同理发给 R2，AS_PATH 是 `65020 65000`。
3. R1 通过 iBGP 发给 R2 和 R3，R2 也发给 R1 和 R3。`next-hop-self` 在这里生效，下一跳被改成 1.1.1.1 或 2.2.2.2，这两个地址 OSPF 可达，路径才有效。没有它，R3 看到的下一跳是 100.0.0.254，路径会因下一跳不可达而无效。
4. R3 收到两条 8.8.8.8：一条下一跳 1.1.1.1，一条下一跳 2.2.2.2。

但是因为bestpath选路原则
BGP 选路顺序大致是:

1. Weight 大者优先(Cisco 私有,仅本机有效)
2. LocalPref 大者优先
3. 本地始发优先
4. AS_PATH 短者优先
5. Origin:IGP < EGP < incomplete
6. MED 小者优先
7. eBGP 优于 iBGP
8. 到下一跳的 IGP metric 小者优先
9. 最老的路径,最后比 Router ID(小者优先)
所以会1.1.1.1优先于2.2.2.2

3.3.3.3 的传播过程：

1. R3 通过 iBGP 发给 R1 和 R2，AS_PATH 为空。
2. R1 向 ISP1 通告，R2 向 ISP2 通告。eBGP 发出时下一跳改成自己的接口地址，并自动加上 `65001`。
3. ISP1 发给 Core 的 AS_PATH 是 `65010 65001`，ISP2 发的是 `65020 65001`。Core 有了两条 3.3.3.3。
4. R1 和 R2 之间不会互相转发 3.3.3.3，因为 iBGP 学来的路由不会再传给其他 iBGP 邻居（水平分割）。

## 阶段 6：观察默认选路（只看，不配置）

```
R1# show ip bgp summary
R2# show ip bgp summary
R3# show ip bgp summary
R3# show ip bgp 8.8.8.8
Core# show ip bgp 3.3.3.3
R3# traceroute 8.8.8.8 source Loopback0
Core# traceroute 3.3.3.3 source Loopback0
```

R3 的选路过程：

- 两条 8.8.8.8 的 Weight、LocalPref（都是 100）、AS_PATH 长度（都是 2）、Origin、MED 全部相同，都是 iBGP，到 1.1.1.1 和 2.2.2.2 的 IGP cost 也相同。
- 最后比 Router ID，1.1.1.1 更小，所以最优是经 R1。
- traceroute 预期：`10.1.13.1 → 100.0.0.254 → 8.8.8.8`。

Core 的选路过程：

- 两条路径都是 eBGP，Cisco 会先选最老的路径，到了 Router ID 才比 11.11.11.11 和 22.22.22.22。
- 所以 Core 默认走哪边取决于哪条先学到，先记下现状再往下做。

## 阶段 7：目标一，LocalPref 改变整个企业的出站

```
! ===== R1 =====
ip prefix-list CORE-LOOPBACK seq 10 permit 8.8.8.8/32
route-map ISP1-IN permit 10
 match ip address prefix-list CORE-LOOPBACK
 set local-preference 100
route-map ISP1-IN permit 100
router bgp 65001
 neighbor 100.0.0.254 route-map ISP1-IN in

! ===== R2 =====
ip prefix-list CORE-LOOPBACK seq 10 permit 8.8.8.8/32
route-map ISP2-IN permit 10
 match ip address prefix-list CORE-LOOPBACK
 set local-preference 200
route-map ISP2-IN permit 100
router bgp 65001
 neighbor 200.0.0.254 route-map ISP2-IN in

R1# clear ip bgp 100.0.0.254 soft in
R2# clear ip bgp 200.0.0.254 soft in
```

网络发生了什么：

- `ip prefix-list` 和 `route-map` 只是定义，还没有绑定到邻居，网络不会有任何变化。
- `permit 10` 只匹配 8.8.8.8/32 并设置 LocalPref。`permit 100` 是空的放行条款，没有它，其他前缀会撞上 route-map 末尾隐含的 deny 被丢掉。
- `neighbor ... route-map ... in`：策略绑定到入方向，但只对之后收到的更新生效，已有的路由还是旧属性。
- `clear ... soft in`：发 route refresh 重新收一遍，邻居不会断。R2 的 8.8.8.8 变成 LP 200。
- R2 把 LP 200 通过 iBGP 带给 R1 和 R3。R1 比较自己的 eBGP 路径（LP 100）和 R2 来的 iBGP 路径（LP 200），LocalPref 比 eBGP/iBGP 优先，所以 R1 的最优变成经 R2。
- R1 的最优路径是 iBGP 学来的，不能再传给 R3，所以 R1 会撤回之前给 R3 的 8.8.8.8。R3 最终多半只剩一条经 R2 的路径，这是正常的。要看两条路径，去 R1 上 `show ip bgp 8.8.8.8`。
- 结果：R3 的 8.8.8.8 变成 `R3 → R2 → ISP2 → Core`。R1 自己访问 8.8.8.8 也会绕到 R2，所以说 LocalPref 是全 AS 一致的出站策略。

验证：

```
R3# show ip bgp 8.8.8.8
R3# traceroute 8.8.8.8 source Loopback0
R1# show ip bgp 8.8.8.8
```

## 阶段 8：目标二，Weight 只改 R3 一台

先清理目标一：

```
R1(config)# router bgp 65001
R1(config-router)# no neighbor 100.0.0.254 route-map ISP1-IN in
R1# clear ip bgp 100.0.0.254 soft in

R2(config)# router bgp 65001
R2(config-router)# no neighbor 200.0.0.254 route-map ISP2-IN in
R2# clear ip bgp 200.0.0.254 soft in
```

清理后的变化：

- R2 的 8.8.8.8 回到 LP 100，R1 的最优变回自己的 eBGP 路径。
- R1 重新通告给 R3，R3 再次看到两条路径，回到阶段 6 的基线。
- 必须先清理，Weight 才有可比的对照：如果 LP 200 还在，R3 本来就走 R2，看不出 Weight 的效果。

再配 Weight（只在 R3 上）：

```
! ===== R3 =====
ip prefix-list CORE-LOOPBACK seq 10 permit 8.8.8.8/32
route-map R2-WEIGHT-IN permit 10
 match ip address prefix-list CORE-LOOPBACK
 set weight 500
route-map R2-WEIGHT-IN permit 100
router bgp 65001
 neighbor 2.2.2.2 route-map R2-WEIGHT-IN in

R3# clear ip bgp 2.2.2.2 soft in
```

网络发生了什么：

- 绑定到 `neighbor 2.2.2.2 ... in` 后，从 R2 学来的 8.8.8.8 在 R3 本机上被打上 Weight 500，其他邻居来的路径 Weight 为 0。
- Weight 是选路第一步，直接压过一切，R3 的最优变成经 R2。
- Weight 是 Cisco 私有属性，只存在于 R3 本机，不会随 BGP 更新传出去。R1、R2 的 BGP 表没有任何变化。R1 自己访问 8.8.8.8 仍然走 ISP1，这是它和 LocalPref 的根本区别。

验证：

```
R3# show ip bgp 8.8.8.8
R3# traceroute 8.8.8.8 source Loopback0
```

## 阶段 9：目标三，AS Path Prepend 影响入站

先清理目标二：

```
R3(config)# router bgp 65001
R3(config-router)# no neighbor 2.2.2.2 route-map R2-WEIGHT-IN in
R3# clear ip bgp 2.2.2.2 soft in
```

再配 Prepend（在 R1，对 ISP1 出站）：

```
! ===== R1 =====
ip prefix-list ENTERPRISE-LOOPBACK seq 10 permit 3.3.3.3/32
route-map TO-ISP1-PREPEND permit 10
 match ip address prefix-list ENTERPRISE-LOOPBACK
 set as-path prepend 65001 65001 65001
route-map TO-ISP1-PREPEND permit 100
router bgp 65001
 neighbor 100.0.0.254 route-map TO-ISP1-PREPEND out

R1# clear ip bgp 100.0.0.254 soft out
```

网络发生了什么：

- 策略绑在出方向，影响的是 R1 对外通告的内容。`soft out` 让 R1 把 3.3.3.3 重新发给 ISP1，AS_PATH 变成 `65001 65001 65001 65001`（3 个手动加的，加上 eBGP 自动加的 1 个）。
- ISP1 转发给 Core 时再加上 65010，AS_PATH 是 `65010 65001 65001 65001 65001`，长度 5。ISP2 那条仍是 `65020 65001`，长度 2。
- Core 比较 AS_PATH，长度 2 小于 5，选择经 ISP2，入站流量变成 `Core → ISP2 → R2 → R3`。
- 这个拓扑里 Core 同时连着两个 ISP。ISP1 自己也会发现经 Core 绕到 ISP2 的路径（`65000 65020 65001`，长度 3）比 R1 直连的（长度 4）更短，于是改选那条，不再把 3.3.3.3 发给 Core。所以 Core 上很可能只看到经 ISP2 这一条路径，这是正常的。

验证：

```
R1# show ip bgp neighbors 100.0.0.254 advertised-routes
Core# show ip bgp 3.3.3.3
Core# traceroute 3.3.3.3 source Loopback0
```

traceroute 预期：`10.0.200.1 → 200.0.0.1 → 3.3.3.3`。

此时 R3 访问 8.8.8.8 仍然默认走 R1，而 Core 回程走 R2，来回路径不同。入站和出站是两套独立的选路，这种非对称路由是正常现象。
