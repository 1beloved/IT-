# iBGP、水平分割

这四个概念是一条因果链：**水平分割**是 iBGP 防环的规则，规则导致需要特殊的邻居结构；

## 一、iBGP 基础

iBGP 是同一个 AS 内的 BGP 邻居，`remote-as` 与本地 `router bgp` 的 AS 号相同。

| 特性              | eBGP     | iBGP       |
| --------------- | -------- | ---------- |
| AS 号            | 不同       | 相同         |
| 默认 TTL          | 1（通常要直连） | 255（不要求直连） |
| 向邻居通告时的下一跳      | 改成自己     | **不改**     |
| 向邻居通告时的 AS_PATH | 加上自己的 AS | **不改**     |
| AD              | 20       | 200        |
| LOCAL_PREF      | 不传递      | **携带并传递**  |

常见配置用 Loopback 建邻居：

```cisco
router bgp 65001
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source loopback0
 neighbor 2.2.2.2 next-hop-self
```

- `update-source loopback0`：用 Loopback 作为源地址，物理链路切换时邻居不断
- `next-hop-self`：把下一跳改成自己，否则 iBGP 邻居拿到的下一跳是外部地址，IGP 里没有就不可达

后面三个问题，根源都是同一个事实：**iBGP 不修改 AS_PATH 和下一跳。**

## 二、iBGP 水平分割

### 规则

从 iBGP 邻居学到的路由，**不会再通告给其他 iBGP 邻居**。

注意范围：**它只限制"iBGP 学来再转给 iBGP"**。从 eBGP 学到的、本地 `network` 产生的，仍然可以通告给所有 iBGP 邻居。

### 为什么有这条规则

eBGP 靠 AS_PATH 防环：收到路由发现 AS_PATH 里有自己的 AS 号，就丢弃。

但路由在 AS 内部转发时，AS_PATH 不变，路由在 iBGP 邻居之间绕圈，AS_PATH 里永远没有变化，**无法判断是否环路**。所以 BGP 干脆规定：iBGP 学到的路由不许再传给 iBGP。每条外部路由只允许从"入口路由器"一跳到其他 iBGP 邻居，天然无环。

### 解决方法

### 1.Full-Mesh 全连接

改成 FULL-MESH 要加什么

只缺一条 R2 与 R4 的 iBGP 会话，两端都要配，而且两端都要加 `next-hop-self`。

R2：

cisco

```cisco
router bgp 65002
 neighbor 4.4.4.4 remote-as 65001
 neighbor 4.4.4.4 update-source Loopback0
 neighbor 4.4.4.4 next-hop-self
```

R4：

cisco

```cisco
router bgp 65002
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source Loopback0
 neighbor 2.2.2.2 next-hop-self
 neighbor 3.3.3.3 next-hop-self
```

#### 为什么两端都要 `next-hop-self`

| 配置      | 原因                                                    |
| ------- | ----------------------------------------------------- |
| R2 → R4 | R2 的 1.1.1.1/32 下一跳是 10.0.12.1，不在 OSPF 里，R4 解析不了，路由无效 |
| R4 → R2 | R4 从 R5 学到的前缀下一跳是 10.0.45.5，同样不在 OSPF 里，R2 解析不了       |
| R4 → R3 | 同理，R3 也需要能解析，否则 R3 上的路由无效，转发时会变成黑洞                    |

漏掉任何一条，对应设备上的路由都会没有 `*`，不会进路由表。

另外，**不需要** `route-reflector-client`。全互联里不需要反射，R3 保持普通 iBGP 路由器就行，加了反而会让现象变得不纯粹。

![[Pasted image 20261012112250.png]]

这是不加Next-hop-self的情况，因为**IBGP不修改下一条**，所以从1.1.1.1来的下一跳是10.1.23.24/网段来的。修改了之后变成了2.2.2.2

#### 二、全互联后，路由怎么传

全互联的关键：**每条外部路由由入口路由器直接告诉所有 iBGP 邻居，一跳到位，不需要任何人转发。**

#### 1.1.1.1/32（R1 引入）

text

```text
R1 ─eBGP→ R2 ─iBGP→ R3
                └─iBGP→ R4 ─eBGP→ R5
```

| 跳   | 发送 → 接收 | 说明                                  |
| --- | ------- | ----------------------------------- |
| 1   | R1 → R2 | eBGP，下一跳 10.0.12.1                  |
| 2   | R2 → R3 | iBGP，下一跳改为 2.2.2.2                  |
| 3   | R2 → R4 | iBGP，下一跳改为 2.2.2.2，**R4 直接从 R2 学到** |
| 4   | R4 → R5 | iBGP 转 eBGP，允许，下一跳改为 10.0.45.4      |

R3 虽然也学到了，但**不需要转给 R4**，因为 R4 已经从 R2 直接拿到了。这就是全互联绕过水平分割的方式：不靠转发，靠每台直接获取。

#### 5.5.5.5/32（R5 引入，需要 R5 先 `network`）

text

```text
R5 ─eBGP→ R4 ─iBGP→ R3
                └─iBGP→ R2 ─eBGP→ R1
```

R4 同时把路由发给 R3 和 R2，下一跳都是 4.4.4.4，R2 再通过 eBGP 转给 R1。此时R2，R4都能学到外部路由。然后R2,R4作为IBGP可以转发给EBGP所以R1，R5也能学到对方的路由。

### 2.route-reflector-client 路由反射器（RR）

#### 一、它是什么操作

这条命令配在**路由反射器（RR）**上，作用是把某个 iBGP 邻居标记为"客户端"：


```cisco
router bgp 65001
 neighbor 4.4.4.4 route-reflector-client
```

- 只配在 RR 上，**客户端自己什么都不用配**，也不知道自己是客户端
- 它的效果是让 RR 可以**打破 iBGP 水平分割**，把一个 iBGP 邻居发来的路由，转发给另一个 iBGP 邻居
- 没有这条命令，R3 就是普通 iBGP 路由器，遵守水平分割

#### 反射规则

RR 把 iBGP 邻居分成两类：客户端和非客户端，规则如下：

| 路由从哪里学到       | 反射给谁                      |
| ------------- | ------------------------- |
| eBGP 邻居       | 所有 iBGP 邻居（本来就允许，和 RR 无关） |
| **客户端**       | 其他**客户端** **和** **非客户端**  |
| **非客户端** iBGP | **只给客户端**                 |

所以 R3 上只把 R4 设为客户端，就能让 R2 和 R4 双向互通：R2 是非客户端，它的路由可以反射给客户端 R4；R4 是客户端，它的路由可以反射给所有人，包括 R2。

#### 反射时附加的两个属性

| 属性            | 作用                                                                          |
| ------------- | --------------------------------------------------------------------------- |
| ORIGINATOR_ID | 记录这条路由最初是哪台路由器（Router ID）引入 AS 的，收到自己发出的路由就丢弃                               |
| CLUSTER_LIST  | 记录这条路由经过了哪些反射器（每个 RR 加上自己的 Cluster ID，默认是自己的 Router ID），RR 发现自己的 ID 已在里面就丢弃 |

这两个属性就是 RR 对"iBGP 无法防环"的补救办法。

#### 反射不会改变什么

默认情况下，反射的路由**不改下一跳、不改 AS_PATH、不改 LOCAL_PREF 和 MED**，原样转发。这是为什么我之前强调要在 R4 上配 `next-hop-self`：RR 反射时下一跳不会变，必须在路由进入 iBGP 之前就设好。

另外，RR 只反射它选出来的**最优路径**，不会把同一前缀的所有路径都发出去。

#### 二、中间隔了两台设备的情况

##### 理解一：iBGP 邻居之间物理上隔着其他路由器

比如 R2 和 R4 之间隔着一台只跑 IGP 的路由器：

text

```text
R2 ── R3(只跑OSPF) ── R4
```

R2 和 R4 用 Loopback 建 iBGP，会话可以正常建立，因为：

- iBGP 的 TTL 默认是 255，不要求直连
- 只要 IGP 让两个 Loopback 互通即可

**反射本身不受影响。** RR 反射靠的是 BGP 会话，和报文经过几台设备无关。

但这时中间那台设备带来的是前面讲过的**黑洞问题**：它不跑 BGP，没有外部前缀的路由，转发目的是外部前缀的流量时会直接丢弃。解决办法还是让它也跑 iBGP，或者用 MPLS。

##### 理解二：iBGP 路由要经过多台 BGP 路由器接力传递

比如：

text

```text
R2 ── R3 ── R4 ── R6      （全部是 iBGP 邻居，一条链）
```

**这里反射不会自动一路传下去，会断在中间。**

原因：一台路由器只有被配成 RR，才能反射。客户端是**不能**反射的，仍遵守水平分割。

假设只在 R3 上配了：

cisco

```cisco
router bgp 65001
 neighbor 4.4.4.4 route-reflector-client
```

| 跳       | 结果                                       |
| ------- | ---------------------------------------- |
| R2 → R3 | R3 学到（来自非客户端 R2）                         |
| R3 → R4 | R3 是 RR，R4 是客户端，**可以反射**                 |
| R4 → R6 | R4 是客户端，不是 RR，R6 是 iBGP 邻居，**水平分割，不能转发** |

结果：**R6 学不到。**

##### 解决办法：层级式反射（Hierarchical RR）

让 R4 同时扮演两个角色：对 R3 是客户端，对 R6 是 RR。

R3：

cisco

```cisco
router bgp 65001
 neighbor 4.4.4.4 route-reflector-client
```

R4：

cisco

```cisco
router bgp 65001
 neighbor 3.3.3.3 remote-as 65001          ! R3 对 R4 来说是普通邻居，不加 client
 neighbor 6.6.6.6 route-reflector-client   ! R6 是 R4 的客户端
```

R6 不需要配置任何反射相关命令。

此时的传递：

| 路由方向        | 传递过程                                                         |
| ----------- | ------------------------------------------------------------ |
| R2 的前缀 → R6 | R3 反射给 R4（R4 是 R3 的客户端）；R4 看 R3 是非客户端，只能反射给自己的客户端，R6 是客户端，可以 |
| R6 的前缀 → R2 | R4 把来自客户端 R6 的路由发给所有人，包括 R3；R3 把来自客户端 R4 的路由发给所有人，包括 R2      |

路径属性也能看到层级：

- ORIGINATOR_ID：由第一个反射的 RR（R3）设置，记录最初引入路由的路由器，例如 2.2.2.2
- CLUSTER_LIST：R3 先加入 3.3.3.3，R4 再加入 4.4.4.4，新的加在前面，防环时每个 RR 都会检查自己的 ID 是否已在其中

#### 其他办法

|办法|说明|
|---|---|
|R6 直接和 R3 建 iBGP，作为 R3 的客户端|最简单，避免链式结构|
|全互联|小规模可用，规模大了扩展性差|
|两台 RR 冗余，所有路由器都是它们的客户端|生产环境最常见的做法|
