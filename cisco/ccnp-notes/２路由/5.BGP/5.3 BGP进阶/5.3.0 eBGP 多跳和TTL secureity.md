
## 一、为什么需要多跳

eBGP 默认有两个限制：

1. 发出的 BGP 报文 **TTL 为 1**，经过任何一台路由器都会减到 0 被丢弃
2. 会做**直连检查**：邻居地址必须在本机某个直连接口的网段内

所以默认情况下，eBGP 邻居必须是**物理直连、用接口地址建邻居**。违反其中任何一条，邻居都会卡在 Active 或 Idle。`ebgp-multihop` 就是解除这两个限制的命令：把 TTL 调大，并关闭直连检查。

## 二、使用场景

### 场景一：用 Loopback 建 eBGP 邻居（最常见）

两台路由器之间有多条并行链路，用接口地址建邻居的话，那条链路断了邻居就跟着断。改用 Loopback 建邻居，只要还有一条链路通，会话就不断，还能在多条链路间做负载分担。虽然物理上直连，但 Loopback 地址 2.2.2.2 不在任何直连网段里，直连检查不通过，所以要配多跳。

### 场景二：邻居中间隔着其他设备

两台 eBGP 路由器之间还隔着三层设备，例如防火墙、运营商的核心路由器、隧道、云服务商的接入网络：

```text
R1 (AS 65001) ── R3 (中间设备) ── R2 (AS 65002)
```

R1 发出的 BGP 报文经过 R3 后 TTL 减 1，必须一开始就设成 2 以上，才能到达 R2。

### 场景三：和路由服务器、云端建立 BGP

对端不在你的直连网段，比如 IXP 的路由服务器、云上的虚拟路由器，本质上就是场景二。

## 三、配置

### 配置 1：邻居隔着中间设备

R1：

```cisco
ip route 10.0.23.2 255.255.255.255 10.0.13.3    ! 到对端地址要有路由

router bgp 65001
 neighbor 10.0.23.2 remote-as 65002
 neighbor 10.0.23.2 ebgp-multihop 2
```

R2：

```cisco
ip route 10.0.13.1 255.255.255.255 10.0.23.3

router bgp 65002
 neighbor 10.0.13.1 remote-as 65001
 neighbor 10.0.13.1 ebgp-multihop 2
```

### 配置 2：Loopback 建 eBGP 邻居

R1：

```cisco
interface loopback0
 ip address 1.1.1.1 255.255.255.255

ip route 2.2.2.2 255.255.255.255 10.0.12.2     ! 链路 1
ip route 2.2.2.2 255.255.255.255 10.0.21.2     ! 链路 2

router bgp 65001
 neighbor 2.2.2.2 remote-as 65002
 neighbor 2.2.2.2 update-source loopback0
 neighbor 2.2.2.2 ebgp-multihop 2
```
- `update-source loopback0`：用 Loopback 作为源地址，物理链路切换时邻居不断
R2 对称配置，邻居写 1.1.1.1，同样 `update-source loopback0` 和 `ebgp-multihop 2`。

### 配置要点

| 要点                  | 说明                                                                              |
| ------------------- | ------------------------------------------------------------------------------- |
| **两端都要配**           | 发出的报文 TTL 由发送方决定，两个方向都要能到达，只配一端会导致单向不通                                          |
| **必须有到对端地址的路由**     | eBGP 双方通常不跑共同的 IGP，要靠静态路由（或 IGP）指向对端 Loopback。多条等价静态路由还能形成负载分担                  |
| **`update-source`** | 用 Loopback 建邻居时，本端的源地址要改成 Loopback，对端的 `neighbor` 地址要与它一致                       |
| **跳数值**             | 取实际需要的最小值。默认为 1，范围 1 到 255，不带数值则为 255                                           |
| **跳数怎么算**           | R1 经过一台中间路由器到 R2，共 2 跳，写 2。直连不经过任何设备，TTL 1 就够，但 Loopback 不在直连网段，仍需关闭直连检查，所以也写 2 |

## 四、`disable-connected-check`：直连 Loopback 的替代写法

如果两台路由器是**物理直连**，只是想用 Loopback 建邻居，不需要放大 TTL，只需要关闭直连检查：

```cisco
router bgp 65001
 neighbor 2.2.2.2 remote-as 65002
 neighbor 2.2.2.2 update-source loopback0
 neighbor 2.2.2.2 disable-connected-check
```

| |`ebgp-multihop N`|`disable-connected-check`|
|---|---|---|
|TTL|调大到 N|保持 1|
|直连检查|关闭|关闭|
|适用|中间隔着设备，或 Loopback 建邻居|物理直连 + Loopback 建邻居|
|安全性|较差，远处的设备也可能接入|较好，TTL 为 1 限制了只有直连邻居|

## 五、安全：TTL Security（GTSM）

多跳放大了 TTL，也意味着远处的攻击者更容易伪造 BGP 报文。GTSM 的思路是反过来：要求收到的报文 TTL 足够大，因为远处的攻击者发不出这么大的 TTL 到达你时依然很大：

```cisco
neighbor 10.0.23.2 ttl-security hops 2
```

- 发出的 TTL 设为 255，只接受 TTL 不小于 255 减 (hops−1) 的报文
- 与 `ebgp-multihop` **不能同时配置**，两者二选一
- 对端也要配置

## 六、验证

```cisco
show ip bgp summary
show ip bgp neighbors 2.2.2.2 | include hops|TTL
show ip route 2.2.2.2
```

`show ip bgp neighbors` 里会显示：

```text
External BGP neighbor may be up to 2 hops away.
```

这行说明多跳已生效。

## 七、排错思路

邻居卡在 Active，按顺序检查：

1. 本机有没有到对端地址的路由：`show ip route 2.2.2.2`
2. 两端是否都配了 `ebgp-multihop`，数值是否够用
3. `update-source` 和对端 `neighbor` 地址是否一致（本端用 Loopback 发，对端要认 Loopback）
4. 中间设备有没有放行 TCP 179，是否有 ACL 或防火墙拦截
5. `remote-as` 是否写对

## 八、一个容易漏掉的坑：递归路由

到对端 Loopback 的路由，**不能是从这个 BGP 邻居自己学来的**。否则：

```text
邻居建立 → 学到路由 → 到邻居的路由改为经由 BGP 学到的路径
→ 邻居地址递归解析出错 → 邻居断开 → 路由消失 → 重新建立 ……
```

邻居会不断震荡（flap）。所以到对端地址的路由要用静态路由或 IGP，不要依赖 BGP 本身。

## 九、速记

| 要点              | 结论                                                    |
| --------------- | ----------------------------------------------------- |
| eBGP 默认         | TTL 1，要求邻居直连                                          |
| 需要多跳的场景         | Loopback 建邻居、中间隔着设备、对端是路由服务器或云端                       |
| 核心命令            | `neighbor x ebgp-multihop N`                          |
| 配置位置            | 两端都要配                                                 |
| 到对端地址的路由        | 静态或 IGP 提供，不能由 BGP 提供                                 |
| 物理直连但用 Loopback | 可用 `disable-connected-check` 代替                       |
| 安全替代            | `ttl-security hops N`，与 multihop 互斥                   |
| 验证              | `show ip bgp neighbors` 里看 "may be up to N hops away" |

# TTL多跳

| |`ebgp-multihop`|`ttl-security`（GTSM）|
|---|---|---|
|目的|**让远处的邻居能通**，放宽限制|**防伪造报文**，收紧限制|
|作用方向|发送：把发出的 TTL 调大|接收：检查收到报文的 TTL|
|发出的 TTL|等于配置的跳数 N|固定 **255**|
|收到报文时|不检查 TTL，只要没被丢弃就收|要求 TTL 足够大，否则丢弃|
|安全性|较差|较好|
|能否同时配置|不能，两者互斥|不能，两者互斥|

### 一、`ebgp-multihop`：只管发送，不验证

cisco

```cisco
neighbor 10.0.23.2 ebgp-multihop 2
```

- 发出的 BGP 报文 TTL 设为 2，这样经过一台中间路由器后，到达对端时还剩 1，不会被丢弃
- 同时关闭直连检查
- **接收时没有任何 TTL 检查**：只要报文能到达，就会交给 BGP 处理

这意味着任何人只要知道邻居的 IP 和端口，就可以从网络任意位置发伪造的 TCP 报文，攻击你的 BGP 会话（比如发 RST 或伪造 UPDATE）。BGP 端口一旦暴露，就会被这样利用。

### 二、`ttl-security`：反过来，验证收到的 TTL

cisco

```cisco
neighbor 10.0.23.2 ttl-security hops 2
```

它的思路来自一个事实：**TTL 只会在路径上减少，不可能增加。**

1. 双方发出的报文 TTL 都设为 255
2. 接收方要求收到的 TTL 不小于 255 减 `hops`，比如 `hops 2` 就要求 TTL 不小于 253
3. 合法邻居最多隔 2 跳，到达时 TTL 一定在 253 到 255 之间，通过检查
4. 远处的攻击者就算把初始 TTL 设成最大值 255，经过十几跳到达你时也只剩两百四十几，**小于 253，被丢弃**

所以攻击者想让报文通过检查，就必须物理上离你足够近，也就是和你只隔 `hops` 跳以内，远程攻击就被挡住了。

补充一个更正：前面我写的"255 减 (hops−1)"不准确，正确的下限是 **255 减 hops**，请以这里为准。

### 三、用一个类比理解

- `ebgp-multihop` 像是"允许远来的客人进门"：门放宽了，但不核对客人身份
- `ttl-security` 像是"只放离得近的人进门"：靠距离判断来的人可不可信

### 四、配置时的注意

1. **两端必须使用同一种机制**。一端 `ebgp-multihop`、另一端 `ttl-security` 通常会失败：
    - 对端 ttl-security 要求 TTL 接近 255，multihop 发出的 TTL 只有 2，被丢弃
2. **两端都要配置**，且 hops 值要覆盖实际跳数。
3. 两者**互斥**，不能同时配置在同一个邻居上。
4. 是否支持、具体命令形式随平台和版本略有不同，在实验里以 `?` 查看为准。

### 五、怎么选

|场景|推荐|
|---|---|
|实验、考试，只要让邻居建起来|`ebgp-multihop`，简单直接|
|物理直连、用 Loopback 建邻居|`disable-connected-check` 或 `ttl-security`|
|生产环境、邻居隔着一两跳、重视安全|`ttl-security`|
|对端不支持 GTSM|只能用 `ebgp-multihop`，配合 ACL 限制来源和 MD5 认证补强|
