
## 一、一页速记（考前扫一遍）

- **选路顺序口诀**：权 → 本 → 始 → (AIGP) → 路 → 源 → M → 外 → 内(IGP) → 老 → RID → 簇 → 邻
- **方向口诀**：Weight / LocalPref 管**出站**；AS_PATH prepend / MED 管**入站**；Community 只是标记，本身不选路。
- **大小口诀**：Weight、LocalPref **大优**；AS_PATH、MED、Origin 码、Cluster List **小/短优**。
- **传播范围**：Weight 不传；LocalPref 只在 iBGP 内传；MED 只给相邻 AS，不再往下传；Community 要 `send-community` 才发。
- **Origin 优先级**：IGP(i) > EGP(e) > Incomplete(?)。`network` 产生 i，`redistribute` 产生 ?。

## 二、属性四分类（两个维度）

|   |   |   |
|---|---|---|
|维度|问题|结果|
|Well-known / Optional|所有 BGP 路由器必须认识吗？|Well-known 必须认识；Optional 可不认识|
|Mandatory / Discretionary|每条 UPDATE 必须带吗？|Mandatory 必带；Discretionary 不一定带|
|Transitive / Non-transitive|不认识时还要继续传吗？|Transitive 继续传；Non-transitive 丢弃|

四类组合：

|   |   |
|---|---|
|类别|属性|
|Well-known Mandatory（公认必遵）|ORIGIN、AS_PATH、NEXT_HOP|
|Well-known Discretionary（公认任意，即"公认可选"，同一类）|LOCAL_PREF、ATOMIC_AGGREGATE|
|Optional Transitive（可选过渡）|AGGREGATOR、COMMUNITY、EXTENDED_COMMUNITIES、AS4_PATH、AS4_AGGREGATOR、LARGE_COMMUNITY|
|Optional Non-transitive（可选非过渡）|MED、ORIGINATOR_ID、CLUSTER_LIST、MP_REACH_NLRI、MP_UNREACH_NLRI|

**Attribute Flags（抓包能看到）**：Optional 0x80 / Transitive 0x40 / Partial 0x20 / Extended Length 0x10。公认属性常见 0x40；可选过渡常见 0xC0；可选非过渡常见 0x80。Optional Transitive 属性被不认识它的路由器转发时，会置 **Partial** 位。

|                           |         |       |        |           |                        |
| ------------------------- | ------- | ----- | ------ | --------- | ---------------------- |
| 属性                        | Type    | 分类    | 范围     | 选路方向      | 作用                     |
| ORIGIN                    | 1       | 公认必遵  | 跨 AS   | i > e > ? | 路由起源                   |

## 四、Cisco Best Path 13 步（必背）

|   |   |   |   |
|---|---|---|---|
|步骤|比较项|偏好|是否标准属性|
|1|Weight|大|否（Cisco 本地）|
|2|Local Preference|大|是|
|3|Locally Originated（network / redistribute / aggregate 产生）|本地产生优先|否|
|4|AIGP|小|是（较少考）|
|5|AS_PATH 长度|短|是|
|6|Origin|i > e > ?|是|
|7|MED|小|是|
|8|eBGP vs iBGP|eBGP 优|否|
|9|IGP Metric to Next-Hop|小|否|
|10|最老的 eBGP 路径（稳定性）|老|否|
|11|Router ID（有 ORIGINATOR_ID 时用它代替 Router ID）|小|部分|
|12|Cluster List 长度|短|是|
|13|Neighbor Address|小|否|

要点：

- 前提是路径**有效**：NEXT_HOP 可达，且路径被同步/策略放行。不可达的路径根本进不了比较。
- 第 5 步之前（Weight、LocalPref、本地始发）都是**本地/本 AS 内**的偏好；第 5 步起才是"网络上看得见"的标准属性比较。
- 第 10 步在部分情况下会被跳过（如开启 `bgp bestpath compare-routerid`）。
- 平时不用背 13 步细节，但必须稳答前 7 步和"为什么这个顺序"。

## 五、逐属性要点与配置

### Weight

- Cisco 私有，只在本路由器有效，不通告给任何邻居。
- 大优。本地产生路由默认 32768，邻居学到的默认 0。
- 适合控制**单台路由器**的出站。

```
router bgp 65001
 neighbor 192.0.2.1 weight 500
```

### Local Preference

- 只在 iBGP 内传，不发给 eBGP 邻居；大优，默认 100。
- 企业多出口控制**出站**最常用。

```
route-map ISP1-IN permit 10
 set local-preference 200
router bgp 65001
 neighbor 203.0.113.1 route-map ISP1-IN in
```

### Origin

- **`network` → i；`redistribute` → ?。注意它不是"来自 IGP 协议"的意思，而是 BGP 里的起源类型。**

### AS_PATH

- 作用：防环、选路、策略匹配、prepend 影响入站。
- 防环：收到的 AS_PATH 含本地 AS，默认拒绝（eBGP）。**iBGP 防环靠水平分割，不靠 AS_PATH**，因为 iBGP 内 AS_PATH 不变。
- Segment 类型：

|                          |                                 |                    |
| ------------------------ | ------------------------------- | ------------------ |
| 类型                       | 含义                              | 场景                 |
| AS_SEQUENCE              | 有序 AS 列表                        | 最常见                |
| AS_SET                   | 无序 AS 集合（显示为 `{65010,65020}`）   | 聚合时 `as-set`       |
| AS_CONFED_SEQUENCE / SET | Confederation 内部 Sub-AS（显示在括号中） | Confederation，对外隐藏 |

- 注意：AS_SET 不管有多少个 AS，**长度只算 1**；Confederation Segment **不计入**长度。

```
route-map PREPEND permit 10
 set as-path prepend 65001 65001 65001
router bgp 65001
 neighbor 198.51.100.1 route-map PREPEND out
```

### NEXT_HOP

- eBGP 学到的路由，下一跳通常是对端地址；**传给 iBGP 默认不变**；RR 反射时也不改。
- iBGP 内下一跳不可达 → 路径无效（show ip bgp 看不到 `*`，或提示 inaccessible）。
- IPv6 / MP-BGP 的下一跳放在 MP_REACH_NLRI 里。
- 常用修复：边界路由器对 iBGP 邻居配 `next-hop-self`；或把外部互联网段放进 IGP。

```
router bgp 65001
 neighbor 2.2.2.2 remote-as 65001
 neighbor 2.2.2.2 update-source Loopback0
 neighbor 2.2.2.2 next-hop-self
```

验证：`show ip bgp <prefix>`、`show ip route <next-hop>`、`show ip cef <next-hop>`

### MED

- 越小越优，影响**邻 AS 进入本 AS**的入口。
- 默认只比较来自**同一相邻 AS**的路径。
- 相关命令（ENARSI 常考）：
    - `bgp always-compare-med`：不同 AS 来的路径也比较 MED。
    - `bgp deterministic-med`：按相邻 AS 分组后比较，消除比较结果受路径到达顺序影响的问题。
    - `bgp bestpath med missing-as-worst`：缺失 MED 视为最大（默认缺失当 0）。
- 学到的 MED 传给 iBGP 邻居，但**不会再通告给其他 AS**。

```
route-map SET-MED permit 10
 set metric 50
router bgp 65001
 neighbor 203.0.113.1 route-map SET-MED out
```

### ORIGINATOR_ID / CLUSTER_LIST（RR 防环）

- RR 反射时加 ORIGINATOR_ID（原始发起者 Router ID）；每过一个 RR 在 CLUSTER_LIST 前面加自己的 Cluster ID。
- 收到的路由带自己的 Router ID 作 ORIGINATOR_ID，或 CLUSTER_LIST 含自己的 Cluster ID，则丢弃。

## 六、Community

普通 Community 32 位，格式 `ASN:VALUE`。Cisco 建议开新格式：`ip bgp-community new-format`。

|   |   |   |
|---|---|---|
|值|含义|对比记忆|
|no-advertise|不发给任何 BGP 邻居（eBGP、iBGP 都不发）|最严|
|no-export|不发给 eBGP 邻居；有 Confederation 时不出 Confederation|次之|
|local-AS|不出本地 Sub-AS（Confederation 内也不发给其他 Sub-AS 的 eBGP 邻居）|比 no-export 更细|
|internet|正常传播，不是"上互联网"|基本无限制|
|gshut|Graceful Shutdown，等价 65535:0，对端是否降 LocalPref 取决于其策略|维护标记|
|none|清除 Community，不是可传播的值|清除|

要点：

- 默认**不会**发给邻居，必须 `neighbor x send-community`；Extended 用 `send-community extended`（或 `both`）。
- `set community` 默认**覆盖**原值，保留要加 `additive`。
- 忘配 `send-community`：本地 `show ip bgp` 能看到，对端收不到，策略自然不生效。

```
ip community-list standard FROM-BRANCH permit 65001:100
route-map MATCH-COMM permit 10
 match community FROM-BRANCH
 set local-preference 150
route-map SET-COMM permit 10
 set community 65001:100 additive
router bgp 65001
 neighbor 203.0.113.1 send-community
 neighbor 203.0.113.1 route-map SET-COMM out
```

三种社区：

|   |   |   |
|---|---|---|
|类型|大小|说明|
|Standard|32 位|普通标记|
|Extended|8 字节|类型字段决定过渡/非过渡；VPN、RT、SoO 常用，后续专题展开|
|Large|12 字节|`Global Admin:Local1:Local2`，适合 4 字节 AS|

## 七、方向速查（排障和面试最常问）

|   |   |   |   |
|---|---|---|---|
|想控制|用什么|在哪配|为什么|
|本路由器出站|Weight|本机|只本地有效|
|整个 AS 出站|Local Preference|入方向（从 ISP 收进来时）或 iBGP 边界|在 iBGP 内传|
|让别人从哪进来（强）|AS_PATH prepend|出方向|路径变长，远端降优先级|
|让邻 AS 从哪进来（弱）|MED|出方向|优先级低于 LocalPref、AS_PATH|
|打标签批量调策略|Community|出/入方向|标记 + 策略调用|

## 八、高频面试题（答题思路）

1. **Weight 和 Local Preference 区别？** Weight 是 Cisco 私有、只在本机有效、不通告；LocalPref 是标准属性，在 iBGP 内传，控制整个 AS 的出站。Weight 比 LocalPref 先比。
2. **怎么控制入站流量？** AS_PATH prepend 为主，MED 为辅（只对相邻 AS 有效）；也可以让上游按 Community 调整其 LocalPref。入站不受自己控制，只能"影响"。
3. **MED 为什么默认只比同一邻 AS 的路径？** 不同 AS 的度量标准不可比，MED 是同一个邻居给出的入口建议。
4. **LocalPref 为什么不传给 eBGP？** 它表达的是本 AS 的内部策略，不应暴露或影响外部 AS。
5. **BGP 里有路由但没有 `*`，怎么排查？** 先看 next-hop 是否可达（`show ip route <nh>`）。典型原因是 eBGP 下一跳传进 iBGP 没改，修复用 `next-hop-self` 或把互联网段引入 IGP。
6. **iBGP 和 eBGP 怎么防环？** eBGP 看 AS_PATH 是否含本地 AS；iBGP 靠水平分割（从 iBGP 学到的不再发给其他 iBGP 邻居），所以需要全互联、RR 或 Confederation。RR 环境额外用 ORIGINATOR_ID 和 CLUSTER_LIST。
7. **no-export 和 no-advertise 区别？** no-advertise 谁都不发；no-export 可以在本 AS 内传（iBGP 邻居），但不发给 eBGP 邻居。
8. **Community 配了对端收不到？** 检查 `neighbor send-community`，以及 route-map 的 `additive` 是否覆盖了原值。
9. **为什么 AS_PATH prepend 不能无限加？** 选路按最短 AS_PATH，prepend 只影响第 5 步；如果对端设了 LocalPref 或 Weight，prepend 无效。部分厂商还对过长 AS_PATH 有限制。

## 九、易错点清单

- "公认任意"和"公认可选"是同一类（Well-known Discretionary），不要当成两类。
- Weight 和 Locally Originated 都不是标准 UPDATE 属性；Locally Originated 排在 LocalPref **之后**、AS_PATH **之前**。
- Router ID 比较：有 ORIGINATOR_ID 时用它代替 Router ID。
- MED 不是传给所有 AS 的；学到的 MED 不会再通告给其他 AS。
- AS_SET 长度算 1；Confederation Segment 不计入长度。
- Community 默认不发送；Extended 要单独 `send-community extended`。
- EXTENDED_COMMUNITIES 属性本身是可选过渡，但具体扩展社区类型字段里还分过渡/非过渡。
- 本表只覆盖常见属性，AIGP、Prefix-SID、BGP-LS 等不在 CCNP 范围内。
