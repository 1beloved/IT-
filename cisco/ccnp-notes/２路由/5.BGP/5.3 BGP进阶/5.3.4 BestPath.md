
# BGP Best Path 选路（CCNP 考试整理版）

> 依据 Cisco IOS / IOS XE 的 BGP Best Path 选择算法（ENCOR / ENARSI 范围）整理。和原笔记不一致的地方见文末“核对与改动说明”。

## 一、先分两层：有效性 → 逐项比较

1. 先判断路径是否**有效**，只有有效路径才进入候选集合。
2. 候选路径按固定顺序逐项比较，**某一步分出胜负就停止**。

常见被排除的路径：

|情况|现象 / 排查|
|---|---|
|Next-Hop 不可达，或递归失败|`show ip bgp` 里没有 `*`，提示 inaccessible；查 `show ip route <next-hop>`|
|被入站策略拒绝（或只作为 received-only 保存，如 `soft-reconfiguration inbound`）|查 route-map / prefix-list / filter-list，`show ip bgp neighbors <ip> received-routes`|
|AS_PATH 含本地 AS（eBGP 环路检测）|默认拒绝，`allowas-in` 可放行|
|开启 `bgp enforce-first-as` 时，eBGP 路径的第一个 AS 不是该邻居的 AS|路径被拒绝|
|不满足同步规则|历史场景，现代网络默认关闭|
|地址族未激活，或邻居没在对应 AF 下通告 NLRI|`show bgp <afi> <safi> summary` 检查|

注意：**RIB-failure 不等于选路失败**。它表示 BGP 已经选中该路径，但因为管理距离或已有更优路由，没有装进 IP RIB（`show ip bgp` 中标 `r`）。

## 二、Best Path 13 步

| 步   | 比较项                    | 规则                                        | 考点备注                                                                |
| --- | ---------------------- | ----------------------------------------- | ------------------------------------------------------------------- |
| 1   | Weight                 | 大优                                        | Cisco 本地属性，不传递；本地产生默认 32768，邻居学到默认 0                                |
| 2   | Local Preference       | 大优                                        | iBGP 内传递，默认 100，控制本 AS 出站                                           |
| 3   | Locally Originated     | 本地注入的优先                                   | 指 `network`、`redistribute`、`aggregate-address` 注入的路径，不是从 iBGP 邻居学来的 |
| 4   | AS_PATH 长度             | 短优                                        | AS_SET 不管含多少个 AS 都算 1；Confederation Segment 不计入                     |
| 5   | Origin                 | IGP(i) > EGP(e) > Incomplete(?)           | `network` 产生 i，`redistribute` 产生 ?                                  |
| 6   | MED                    | 小优                                        | 默认只比较来自同一相邻 AS 的路径；缺失 MED 按 0                                       |
| 7   | eBGP vs iBGP           | eBGP 优                                    | 见文末对 Confederation 的说明                                              |
| 8   | IGP Metric to Next-Hop | 小优                                        | 比的是到 BGP 下一跳的 IGP 代价，不是到目的前缀的代价                                     |
| 9   | Multipath 检查           | 满足等价条件且启用 `maximum-paths` 时，多条路径可同时装入 RIB | 不改变“Best Path 唯一”这一点                                                |
| 10  | 最老的 eBGP 路径            | 先收到的优先                                    | 只对外部路径有意义；`bgp bestpath compare-routerid` 会跳过此步                     |
| 11  | Router ID              | 小优                                        | RR 环境中有 ORIGINATOR_ID 时，用它代替 Router ID 比较                           |
| 12  | Cluster List 长度        | 短优                                        | 只在 RR 环境出现                                                          |
| 13  | Neighbor Address       | 小优                                        | 最后的平局判断                                                             |

**速记口诀**：高 Weight、高 LocalPref、本地产生、短 AS_PATH、低 Origin、低 MED、eBGP、低 IGP Metric、Multipath、老 eBGP、低 Router ID、短 Cluster List、低邻居地址。

**理解提示**：

- 第 1～3 步是“本地 / 本 AS 内”的偏好，第 4 步起才是路径本身携带的属性比较。
- 本地产生的路由默认 Weight 就是 32768，所以通常在第 1 步就已经胜过邻居学来的（默认 0）；第 3 步主要在 Weight 被改动或相等时起作用。
- AIGP 在较新的 Cisco 文档里位于第 3 步之后、AS_PATH 之前，只有启用 AIGP 才生效，ENCOR / ENARSI 基本不考，这里不单列。

## 三、关键细节

**Weight / LocalPref**

- Weight 只影响本机；LocalPref 影响整个 AS 的出站，是企业双出口做主备最常用的属性。

**MED**

- 默认只在同一相邻 AS 的路径之间比较。
- `bgp always-compare-med`：强制跨相邻 AS 比较。
- `bgp deterministic-med`：同一相邻 AS 的路径先分组比较，结果不再受路径接收顺序影响。
- `bgp bestpath med missing-as-worst`：缺失 MED 视为最大（默认按 0，即最优）。

**eBGP / iBGP 与 IGP Metric**

- 来源类型比完仍相同，才继续比较 IGP Metric to Next-Hop。

**Multipath**

- 命令：eBGP 用 `maximum-paths <n>`，iBGP 用 `maximum-paths ibgp <n>`，默认只有 1 条。
- 常见等价条件：Weight、LocalPref、AS_PATH 长度、Origin、MED、来源类型、IGP Metric 都一致；eBGP 多路径通常还要求来自同一相邻 AS，否则需要 `bgp bestpath as-path multipath-relax`。
- 即使装入了多条，仍然会选出一条 Best Path（`show ip bgp` 里多路径条目会带 `m` 标记）。

**最老 eBGP 路径**

- 目的是降低路由翻动：较早收到的外部路径不会被新来的等价外部路径轻易抢占。

**Router ID / Originator ID / Cluster List**

- 没有通过 Multipath 装入多条时，需要继续选出单一 Best Path，先比 Router ID（有 ORIGINATOR_ID 则比它）。
- Cluster List 只在 RR 环境中出现，越短越优。

## 四、读 `show ip bgp` 输出

```
Network          Next Hop        Metric LocPrf Weight Path
```

|字段|看什么|
|---|---|
|`*`|路径有效（下一跳可达）|
|`>`|已被选为 Best Path|
|`i`（状态列）|从 iBGP 邻居学到|
|`r`|RIB-failure|
|`s`|被抑制（suppressed）|
|Metric|MED|
|LocPrf|Local Preference|
|Weight|本地 Weight|
|Path 末尾 `i` / `e` / `?`|Origin 类型|

注意：这是**显示顺序**，不是比较顺序。

排查顺序：

1. 没有 `*`：先查 Next-Hop 可达性、AS_PATH、入站策略。
2. 有 `*` 没 `>`：BGP 没选它，按 13 步逐项对比。
3. 有 `>` 但不在路由表：查 RIB-failure、管理距离、是否已有更优路由。
4. 选路不符合预期：按 Weight → LocalPref → AS_PATH → Origin → MED 的顺序逐项比较。

常用命令：`show ip bgp`、`show ip bgp <prefix>`（看详细属性）、`show bgp ipv4 unicast`、`show ip bgp neighbors <ip> routes`。

## 五、案例推演

|案例|对比|结论|考点|
|---|---|---|---|
|1. Weight 最高优先|A：LocPrf 100、Weight 500；B：LocPrf 200、Weight 0|A 胜|先比 Weight，再比 LocalPref；Weight 只影响本机|
|2. LocalPref 控制全 AS 出站|R1 从 ISP-A 学到 LocPrf 200；R2 从 ISP-B 学到 LocPrf 100|R1 的路径胜|LocalPref 在 iBGP 内传递，全 AS 出站一致|
|3. 短 AS_PATH 优先|A：65010 65100 65200；B：65020 65200，前面属性相同|B 胜|Prepend 就是人为拉长 AS_PATH 降低吸引力|
|4. MED 只比同一邻 AS|A 来自 AS 65010，MED 50；B 来自 AS 65020，MED 10|默认不比较 MED，继续比后面的步骤|要跨 AS 比较需配 `always-compare-med`|
|5. Next-Hop 不可达|A：LocPrf 200 但下一跳不可达；B：LocPrf 100 且有效|B 胜|先查有效性，A 根本不进入比较|

## 六、高频考点与易错点

- 13 步顺序和“大优 / 小优 / 短优”的方向要背熟。
- Weight 不是标准 BGP 属性，不会写进 UPDATE。
- Locally Originated 指本路由器注入的路径，不是 iBGP 学来的路径。
- AS_SET 长度算 1，Confederation Segment 不计入 AS_PATH 长度。
- MED 默认只比同一邻 AS；缺失 MED 默认按 0。
- `compare-routerid` 会跳过“最老 eBGP”这一步。
- Multipath 不改变 Best Path 的唯一性。
- RIB-failure 不是选路失败。
- 方向记忆：Weight / LocalPref 管出站；AS_PATH prepend / MED 影响入站。

## 七、核对与改动说明

- 我上一版《BGP 路径属性（考试 & 面试版）》把 AIGP 列为第 4 步、没有单列 Multipath 检查。本版改为 Cisco 常见的 13 步（含 Multipath 检查），AIGP 作附注，请以本版为准。
- 第 7 步 Confederation：原笔记写“eBGP > Confederation eBGP > iBGP”。我记得 Cisco 官方文档对这一步的写法是：含 AS_CONFED_SEQUENCE 的路径按内部路径处理，不再区分 confed-external 和 internal。不同资料说法有出入，这里我没有联网核对，建议对照你所用的 Cisco 官方教材或文档确认。考试中 Confederation 选路极少单独考。
- 原笔记的流程图在复制后文字被打乱，已改为表格；原“关键细节”第 13 条表述绕，已并入 Multipath 和 Router ID 两节重写。
- 案例 4 补上了后续结论：跳过 MED 后继续往下比，不会因为 MED 而卡住。
