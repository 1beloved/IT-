
### 黑洞的本质

BGP 路径上的**每一跳**，都必须能为目的地址转发。边界路由器知道外部前缀，不代表核心路由器也知道。**黑洞**是 iBGP 在中转 AS 里的典型故障；**同步**是早期用来防黑洞的机制。

### 另一类常见问题：下一跳不可达

iBGP 不改下一跳。R3 收到 R1 通告的前缀 X，下一跳可能是 AS100 的地址（如 10.0.1.1）。如果 IGP 里没有到这个地址的路由，这条 BGP 路由就**无效**（没有 `*`），不会进路由表。这不是黑洞，而是路由用不了，解决办法是在 R1 上配 `neighbor R3 next-hop-self`，或者把外部链路网段通过 IGP 宣告出去（注意设成 passive）。

### 解决办法

| 办法                  | 做法                          | 评价               |
| ------------------- | --------------------------- | ---------------- |
| 核心路由器也跑 iBGP        | 全互联或 RR                     | 最直接，需要核心路由器有足够内存 |
| BGP-free core（MPLS） | 边界之间打标签，核心只做标签转发，不看 IP 目的地址 | 运营商主流方案          |
| 把 BGP 重分发进 IGP      | 边界上 `redistribute bgp`      | 规模、属性丢失、环路风险，不推荐 |
| 核心配静态路由或默认路由指向边界    | 手工写                         | 只适合小规模，不能动态跟随    |
|                     |                             |                  |

## iBGP 同步（Synchronization）不推荐使用

### 作用

同步是早期 Cisco 为防止黑洞设计的机制：

> **从 iBGP 学到的路由，只有 IGP 路由表里也有这条路由（精确匹配前缀和掩码），才会被认为有效，才能通告给 eBGP 邻居。**

对应上面的场景：

- R3 从 iBGP 学到 X
- 开启同步后，R3 要先检查：IGP 里有没有 X？没有
- R3 **不会**把 X 通告给 AS 300，也不会把这条路由当作最优路径使用
- AS 300 不知道 X，也就不会把流量送进来，黑洞就避免了

逻辑是：中间路由器（R2）如果不跑 BGP，就只能靠 IGP 转发，所以必须保证 IGP 里有这条路由，边界才敢对外通告。

### 怎么满足同步条件

让 IGP 里出现 X：

- 在 R1 上把 BGP 路由重分发进 IGP
- 或者在 IGP 里直接静态/宣告这条前缀

这意味着要把外部路由灌进 IGP，正是前面说过的、规模和属性都不可取的做法。**同步本身逼着你去做一件不好的事**，这也是它被淘汰的原因之一。

### 现象

BGP 表里这条路由是有效的（valid），但没有 `>` 最优标记，用 `show ip bgp x.x.x.x` 能看到 `not synchronized`：

```text
Origin IGP, localpref 100, valid, internal, not synchronized
```

### 配置与现状

```cisco
router bgp 65001
 synchronization        ! 开启
 no synchronization     ! 关闭
```

- 很早的 IOS 默认开启，**现代 IOS 默认关闭**
- 实验里 iBGP 路由"valid 但没 `>`"，且显示 `not synchronized`，就是同步被开启了
- 同步依赖 IGP 路由精确匹配，使用 OSPF 时还要求 OSPF Router ID 和 BGP Router ID 相同，是常见的实验坑

### 什么时候可以关闭同步

满足任一条件即可：

1. 本 AS 不是中转 AS（你的流量不会穿越你）
2. AS 内**所有**路由器都跑 iBGP（全互联或 RR），每台都有完整 BGP 路由
3. 用 MPLS 做 BGP-free core，核心根本不查 IP

现代网络几乎都满足这些条件，所以同步基本不用了。



## 速记

|概念|一句话|
|---|---|
|iBGP|同 AS 邻居，不改下一跳、不改 AS_PATH，AD 200|
|水平分割|iBGP 学到的路由不转给其他 iBGP 邻居，防环|
|解决水平分割|全互联、RR、联盟|
|黑洞|核心路由器没有外部路由，吃掉穿越的流量|
|同步|IGP 里没有这条路由，iBGP 路由就不生效、不通告给 eBGP|
|同步现状|现代 IOS 默认关闭，被 RR、MPLS 取代|
|下一跳问题|iBGP 不改下一跳，需 `next-hop-self`|

## 验证命令

```cisco
show ip bgp summary                 ! iBGP 邻居状态，AS 号与本地相同

show ip route 10.0.0.0              ! 路由表里有没有，AD 是否为 200
show ip bgp neighbors x.x.x.x       ! 看 BGP neighbor is x, remote AS ..., internal link
```
