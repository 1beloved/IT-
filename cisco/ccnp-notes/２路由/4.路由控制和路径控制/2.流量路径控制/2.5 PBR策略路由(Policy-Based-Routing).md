# PBR(策略路由)与路由策略

## 1. 一句话区别

|       | 策略路由 PBR                    | 路由策略 Route Policy           |
| ----- | --------------------------- | --------------------------- |
| 英文    | Policy-Based Routing        | Routing Policy              |
| 作用对象  | **数据包**(转发平面)               | **路由条目**(控制平面)              |
| 解决的问题 | "这个包该往哪走"                   | "哪些路由能进路由表 / 能被发布 / 属性怎么改"  |
| 匹配依据  | 源地址、目的地址、协议、端口、包长等          | 路由前缀、metric、tag、AS-path 等   |
| 应用位置  | 接口入方向 `ip policy route-map` | 重分发、BGP/OSPF/EIGRP 的过滤与属性修改 |
| 结果    | 绕过路由表,按 `set` 指定的下一跳转发      | 改变路由表内容或路由通告内容              |



**共同点:两者都用 `route-map` 实现,`route-map` 只是工具,用在哪里决定了它是 PBR 还是路由策略。**

记忆口诀:**路由策略管"路由表里有什么",策略路由管"这个包怎么走"。**

你正在学的 prefix-list、distribute-list、重分发里的 route-map,都属于路由策略。

---

## 2. PBR 的工作原理

普通转发只看**目的地址**,做最长匹配。PBR 在这之前插入一步:

```
包进入接口 → 检查接口上是否应用了 PBR
    ├─ 匹配 route-map 的 permit 序列 → 按 set 指定的方式转发(绕过路由表)
    └─ 匹配 deny 序列 / 没有任何序列匹配 → 回到正常路由表转发
```

⚠️ 这里有个与路由策略相反的细节:**PBR 里 route-map 末尾的隐含 deny,意思是"走正常路由",不是丢包。**

---

## 3. PBR 配置逐字段拆解

场景:财务网段 192.168.1.0/24 走 ISP1,其他流量走默认路由。

```
access-list 101 permit ip 192.168.1.0 0.0.0.255 any

route-map PBR-DEMO permit 10
 match ip address 101
 set ip next-hop 10.1.1.2

interface GigabitEthernet0/0
 ip policy route-map PBR-DEMO
```

### ① 扩展 ACL:定义"哪些包要被策略处理"

```
access-list 101 permit ip 192.168.1.0 0.0.0.255 any
```

|字段|含义|
|---|---|
|`101`|扩展 ACL 编号(100-199)|
|`permit`|匹配到的包**交给策略处理**(不是放行/拒绝)|
|`ip`|协议,也可以是 `tcp`/`udp`/`icmp`|
|`192.168.1.0 0.0.0.255`|**第一个地址 = 源地址**(反掩码)|
|`any`|**第二个地址 = 目的地址**,any 表示任意|

> 扩展 ACL 的固定顺序:**协议 → 源 → 目的**。用 `tcp` 时,端口跟在对应地址后面,例如 `permit tcp 192.168.1.0 0.0.0.255 any eq 80`,这里 `eq 80` 是**目的端口**,因为它跟在目的地址后。

### ② route-map:定义"匹配什么、怎么转发"

```
route-map PBR-DEMO permit 10
```

|字段|含义|
|---|---|
|`route-map`|创建/进入 route-map|
|`PBR-DEMO`|名字,自定义,接口上要引用|
|`permit`|匹配该序列的包**执行 set 动作**;若是 `deny`,匹配的包**不做 PBR,走正常路由表**|
|`10`|序号,从小到大依次匹配,命中即停止,建议 10、20、30 留空隙|

```
 match ip address 101
 set ip next-hop 10.1.1.2
```

|字段|含义|
|---|---|
|`match ip address 101`|条件:包要匹配 ACL 101|
|`set ip next-hop 10.1.1.2`|动作:把下一跳强制改成 10.1.1.2。**必须是直连可达的地址**|

### ③ 接口上调用

```
interface GigabitEthernet0/0
 ip policy route-map PBR-DEMO
```

- 应用在**流量进入的接口**(入方向),这里是内网侧接口。
- 只对**经过路由器转发**的流量生效。
- 路由器**自己发出**的流量(如自身 ping、telnet)要用 `ip local policy route-map PBR-DEMO`。

## 4. 常用 set 命令对比

|命令|行为|
|---|---|
|`set ip next-hop X`|强制使用下一跳 X,**优先于路由表**|
|`set ip default next-hop X`|**仅当路由表没有明确路由时**才使用(默认路由不算明确路由),相当于"兜底"|
|`set interface Gi0/1`|强制从该接口发出(点到点链路用;以太网上不推荐,会导致 ARP 问题)|
|`set ip next-hop verify-availability X 10 track 1`|配合 IP SLA/track 检测下一跳可达性,**不通则自动回退**到路由表|
|`set ip dscp / precedence`|只改 QoS 标记,不改转发路径|

⚠️ 普通 `set ip next-hop` 只检查下一跳是否在路由表中可解析,**不会探测它是否真的活着**。生产环境做双出口选路,建议配合 track 使用。

## 5. 路由策略对比示例

同样是 route-map,这次用在**重分发**:

```
ip prefix-list P1 seq 5 permit 10.1.0.0/16 le 24

route-map OSPF-TO-EIGRP permit 10
 match ip address prefix-list P1
 set metric 10000 100 255 1 1500

router eigrp 100
 redistribute ospf 1 route-map OSPF-TO-EIGRP
```

|字段|含义|
|---|---|
|`match ip address prefix-list P1`|匹配的是**路由前缀**(不是数据包)|
|`set metric ...`|给被引入的路由设置 EIGRP 的五个度量值(带宽、延迟、可靠性、负载、MTU)|
|`redistribute ospf 1 route-map ...`|把 OSPF 1 的路由**引入** EIGRP,并经过这个 route-map 过滤和改属性|

**关键差异:这里隐含 deny 的意思是"这条路由不引入",即真正被拒绝。** 而 PBR 里的隐含 deny 是"回到正常转发"。

---

## 6. 并排对照

```
          路由策略                              策略路由(PBR)
          ────────                              ──────────────
 match →  路由前缀 / metric / tag               源/目的 IP、协议、端口
 set   →  metric、tag、local-pref、AS-path      next-hop、出接口、DSCP
 调用  →  redistribute / neighbor in/out        ip policy route-map(接口)
          distribute-list                       ip local policy route-map
 deny  →  路由被拒绝                            包走正常路由表
 影响  →  路由表 / 路由通告                     单个数据包的转发路径
```

## 7. 验证与排错

```
show route-map PBR-DEMO          ! 看各序列和命中次数
show ip policy                   ! 看哪些接口应用了哪个策略
show access-lists 101            ! ACL 命中计数
debug ip policy                  ! 实时看包是否被策略转发(慎用)
```

**常见故障:**

1. ACL 的源/目的写反,导致匹配不到。
2. 策略应用在**出方向接口**,而 PBR 要应用在**入方向**接口。
3. `set ip next-hop` 的地址不直连,或者在路由表里不可解析。
4. 忘记回程流量:去程走 ISP1,回程如果走了别处,会出现**非对称路由**,遇到状态防火墙或 NAT 就会断。
5. PBR 通常在**软件/CEF 路径**处理,大流量时要关注设备性能。

---

## 8. 总结

- **路由策略**是在"路由"这一层动手脚,影响的是路由表和路由通告。
- **PBR** 是在"转发"这一层动手脚,影响的是单个数据包的出口。
- 两者共用 `route-map` 语法,但**隐含 deny 的含义不同**,这是最容易考到的细节。
