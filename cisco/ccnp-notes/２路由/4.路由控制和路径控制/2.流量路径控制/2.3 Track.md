# Track 与 IP SLA 的配合

## 1. 分工:一个负责"测",一个负责"判"和"通知"

| 组件                  | 角色                                 | 输出                   |
| ------------------- | ---------------------------------- | -------------------- |
| **IP SLA**          | 探测者:发包、收包、记录结果                     | 原始数据:成功/失败、RTT、丢包    |
| **Track**           | 判官 + 传话人:把原始数据转成 Up/Down,并通知引用它的功能 | 一个布尔状态:**Up / Down** |
| **路由/HSRP/PBR/EEM** | 执行者:根据 Track 状态改变行为                | 撤销路由、降优先级等           |

IP SLA 本身**不会**直接去改路由。它只产生数据,中间必须有 Track 做翻译,因为路由、HSRP 这些功能只认"一个对象是 Up 还是 Down",不懂 RTT、丢包是什么。

## 2. 配合流程

```
IP SLA 操作 1          Track 1               静态路由
┌──────────┐      ┌────────────┐      ┌──────────────────┐
│ 每5秒ping │ ───▶ │ 订阅探测结果 │ ───▶ │ ip route ... track 1 │
│ 记录成败  │      │ 转成Up/Down │      │ Up→保留  Down→撤销   │
└──────────┘      └────────────┘      └──────────────────┘
```

1. IP SLA 周期性探测,更新自己的状态
2. Track 持续"盯着"这个 IP SLA 操作的状态
3. 状态变化时,Track 状态翻转
4. 所有引用该 Track 的功能被立即通知,各自执行动作

这是**事件驱动**的:Track 状态一变,路由表马上更新,不需要轮询。

## 3. 配置上的对应关系

```
ip sla 1                                   ! ① 定义探测
 icmp-echo 8.8.8.8 source-interface Gi0/0
 frequency 5
ip sla schedule 1 life forever start-time now

track 1 ip sla 1 reachability              ! ② Track 绑定 IP SLA 操作 1
 delay down 10 up 20

ip route 0.0.0.0 0.0.0.0 203.0.113.1 track 1   ! ③ 路由绑定 Track 1
ip route 0.0.0.0 0.0.0.0 198.51.100.1 250
```

三处编号的引用链:`ip route ... track 1` → `track 1 ip sla 1` → `ip sla 1`。这三个编号是各自独立的命名空间,只是恰好都写成 1,**不要求相同**。

## 4. Track 判定 IP SLA 状态的两种方式

```
track 1 ip sla 1 reachability
track 2 ip sla 1 state
```

| 关键字              | 判定依据         | Down 的条件                              |
| ---------------- | ------------ | ------------------------------------- |
| **reachability** | 探测是否成功       | 探测失败(超时、不可达)                          |
| **state**        | 操作的整体状态是否 OK | 探测失败 **或** 触发了 threshold 违规(如 RTT 过高) |

简单理解:

- `reachability`:只关心"通不通"
- `state`:还关心"质量好不好",例如配了 `threshold 100`,RTT 超过 100ms 也会被判 Down

做单纯的链路切换,用 `reachability` 最常见、最稳妥。

## 5. Delay:防止抖动

```
track 1 ip sla 1 reachability
 delay down 10 up 20
```

- `delay down 10`:探测失败后,**持续 10 秒仍失败**才把 Track 置 Down
- `delay up 20`:探测恢复后,**持续 20 秒稳定**才把 Track 置 Up

没有 delay,一次偶发丢包就会让路由撤销再恢复,造成路由震荡。通常 **down 设短、up 设长**:故障要尽快切走,恢复要谨慎确认稳定后再切回。

## 6. Track 的其他用法

Track 不只能绑 IP SLA,也可以跟踪:

```
track 10 interface Gi0/1 line-protocol     ! 接口状态
track 11 ip route 10.0.0.0/8 reachability  ! 路由表里是否存在某条路由
track 12 list boolean or                   ! 组合多个 Track
 object 1
 object 2
```

其中 **`track list boolean`** 常和 IP SLA 搭配,解决单目标误判:

```
track 100 list boolean or
 object 1        ! 探测 8.8.8.8
 object 2        ! 探测 1.1.1.1
```

任意一个目标可达,Track 100 就保持 Up;**两个都不通**才判 Down。

## 7. 验证命令

```
show track 1
show ip sla statistics 1
show ip route
show ip sla summary
```

`show track 1` 会显示当前状态、状态变化次数和上次变化时间,排错时第一个看它。

## 一句话总结

**IP SLA 负责产生"探测事实",Track 负责把事实翻译成 Up/Down 并广播给引用者**。路由、HSRP 等功能不直接依赖 IP SLA,只依赖 Track,所以 Track 是整个联动机制的"接口层"。
