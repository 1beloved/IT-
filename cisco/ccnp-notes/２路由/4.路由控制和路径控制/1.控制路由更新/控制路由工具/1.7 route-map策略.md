
## 1. 是什么

route-map 是一个更灵活的路由工具，采用"条件判断 + 动作"的逻辑，本身不生效，要被其他功能调用：

- 控制路由的发布和接收（如 distribute-list 调用）
- 控制路由的重分发（`redistribute ... route-map`）
- 策略路由 PBR：决定数据包走哪条路
- BGP：过滤和修改路径属性

## 2. 基本结构

```
route-map 名字 {permit | deny} 序号
 match 条件
 set 动作
```

| 部分            | 说明                       |
| ------------- | ------------------------ |
| 名字            | 被调用时引用                   |
| permit / deny | 匹配后**执行**还是不执行，默认 permit |
| 序号            | 从小到大依次检查                 |
| match         | 匹配条件（可选）                 |
| set           | 匹配后的动作（可选）               |

## 3. 与 ACL 的异同

**相同点**

- 规则从上往下执行，一旦匹配则结束，否则继续往下查找
- 末尾隐含 `deny any`
- 先匹配条件，再执行动作

**最大区别**

- ACL 只能匹配并放行或拒绝
- route-map 还能用 `set` 修改路由的"属性"（度量、tag、metric-type、下一跳等）

**结构差异**

- ACL 每一行是一条规则
- route-map 每个序号是一个规则块，块内可以有多条 match 和 set

## 4. 执行逻辑

1. 从最小序号开始，检查路由是否满足 match
2. 满足且为 permit：执行 set，放行，不再往下检查
3. 满足且为 deny：直接拒绝，不再往下检查，set 不执行
4. 不满足：继续检查下一个序号
5. 全部不满足：被隐含的 `deny any` 拒绝

## 5. match 的逻辑关系（易错）

| 写法                                                 | 关系              |
| -------------------------------------------------- | --------------- |
| 同一条 match 里写多个值：`match ip address prefix-list A B` | **或**           |
| 同一序号里写多条不同类型的 match                                | **与**           |
| 序号里没有 match                                        | 匹配所有路由（常用于结尾兜底） |
| 序号里没有 set                                          | 只放行或拒绝，不改属性     |

## 6. 常用 match 和 set

| 用途   | match                          | set                             |
| ---- | ------------------------------ | ------------------------------- |
| 前缀   | `match ip address prefix-list` |                                 |
| 标记   | `match tag`                    | `set tag`                       |
| 路由类型 | `match route-type`             | `set metric-type type-1/type-2` |
| 接口   | `match interface`              |                                 |
| 度量   | `match metric`                 | `set metric`                    |
| 下一跳  | `match ip next-hop`            | `set ip next-hop`（PBR 常用）       |

## 7. 在重分发中的应用

### 重分发注意事项

1. 只能重分发路由表中已存在的该协议路由
2. 重分发有方向性：影响其他设备的路由表，不影响自身路由表（ASBR 上仍显示原协议）
3. 除了该协议的路由，还会带上运行该协议的**直连接口网段**
4. 重分发进 EIGRP 时，必须手动指定五个度量参数（带宽、延迟、可靠性、负载、MTU），直连、静态、EIGRP 不同 AS 之间除外
    - 注意：这里是五个度量数值，不是 K1 到 K5 权重系数
5. 重分发进 OSPF 要加 `subnets`，否则子网丢失

### 只引入一条路由（示例）

```
1.先创建好前缀列表的匹配路由

ip prefix-list ONLY-ONE seq 5 permit 10.1.1.0/24

2.此时创建路由策略，设置匹配条件为ONLY_ONE

route-map OSPF-TO-EIGRP permit 10
 match ip address prefix-list ONLY-ONE

3.重分发

router eigrp 100
 redistribute ospf 1 route-map OSPF-TO-EIGRP metric 10000 100 255 1 1500
```

- 未匹配的路由被隐含 deny 挡住，即不被重分发
- prefix-list 是精确匹配，匹配范围要用 `ge` / `le`

### 双向重分发防环（tag）

```
route-map EIGRP-TO-OSPF deny 10
 match tag 100
 
route-map EIGRP-TO-OSPF permit 20
 set tag 200

route-map OSPF-TO-EIGRP deny 10
 match tag 200
 
route-map OSPF-TO-EIGRP permit 20
 set tag 100

router ospf 1
 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF
router eigrp 100
 redistribute ospf 1 route-map OSPF-TO-EIGRP metric 10000 100 255 1 1500
```

思路：重分发时打 tag，另一个方向看到这个 tag 就拒绝，路由不会被送回原来的域。

## 8. deny 的含义随场景变化

| 调用场景               | deny 的含义              |
| ------------------ | --------------------- |
| 重分发                | 不重分发（原路由表里的路由仍存在）     |
| PBR                | 不做策略路由，按正常路由表转发（不是丢包） |
| distribute-list 过滤 | 不接收或不发布该路由            |

## 9. 三个易错点

1. **`set` 只在 permit 序号里执行，deny 序号里写了无效**
2. **用于 distribute-list 过滤时，只有 `match` 起作用，改属性的 `set` 无效**
3. **序号顺序错误会导致提前命中；漏写兜底的 `permit` 会导致其余路由被挡住**

## 10. 与协议相关的补充

- OSPF 的 `distribute-list in` 只影响本机路由表，LSA 仍会泛洪；`distribute-list out` 只对重分发有效
- 重分发的依据是路由表（RIB），不是数据库
- 重分发进 OSPF 的默认种子度量是 20（BGP 为 1），进 EIGRP、RIP 没有默认值
- E1：度量 = 种子度量 + 到 ASBR 的内部 cost；E2（默认）：全域保持种子度量
- AD：EIGRP 内部 90 / 外部 170，OSPF 110

## 11. 验证与排错

|命令|用途|
|---|---|
|`show route-map`|查看 match、set 及各序号命中次数|
|`show ip prefix-list`|检查 prefix-list|
|`show ip route`|看 `D EX`、`O E2` 等|
|`show ip ospf database external`|看 Type 5 LSA|
|`show ip eigrp topology`|看 EIGRP 拓扑表|
|`show ip protocols`|看重分发配置|

命中次数为 0，说明该序号的条件没写对。

配置
***不要把match ip address prefix-list EIGRP写成match ip address EIGRP***
**因为一个是匹配ACL一个是匹配prefix-list.!!!!!**

```  R2

router eigrp 90
 network 10.1.1.0 0.0.0.255
 redistribute ospf 110 route-map O_T_E
 eigrp router-id 2.2.2.2

router ospf 110
 router-id 2.2.2.2
 redistribute eigrp 90 subnets route-map E_T_O
 network 40.1.1.0 0.0.0.255 area 0
 network 50.1.1.0 0.0.0.255 area 0

 
ip prefix-list EIGRP seq 5 permit 192.168.1.0/24 le 32
ip prefix-list EIGRP seq 10 deny 0.0.0.0/0 le 32

ip prefix-list OSPF seq 5 permit 192.168.2.0/24 le 32
ip prefix-list OSPF seq 10 deny 0.0.0.0/0 le 32

route-map E_T_O deny 10
 match tag 1

route-map E_T_O permit 20
 match ip address prefix-list EIGRP
 set tag 100


route-map O_T_E deny 10
 match tag 100

route-map O_T_E permit 20
 match ip address prefix-list OSPF
 set metric 10000 100 255 1 1500
 set tag 1



```


```  R4
router eigrp 90
 network 20.1.1.0 0.0.0.255
 redistribute ospf 110 route-map O_T_E
 eigrp router-id 4.4.4.4

router ospf 110
 router-id 4.4.4.4
 redistribute eigrp 90 subnets route-map E_T_O

ip prefix-list EIGRP seq 5 permit 192.168.1.0/24
ip prefix-list EIGRP seq 10 deny 0.0.0.0/0 le 32

ip prefix-list OSPF seq 5 permit 192.168.2.0/24
ip prefix-list OSPF seq 10 deny 0.0.0.0/0 le 32

route-map E_T_O deny 10
 match tag 1

route-map E_T_O permit 20
 match ip address prefix-list EIGRP
 set tag 100

route-map O_T_E deny 10
 match tag 100

route-map O_T_E permit 20
 match ip address prefix-list OSPF
 set metric 10000 100 255 1 1500
 set tag 1

```
