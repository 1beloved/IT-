命令：
```python
access-list 10(seq) permit/deny 10.1.0.0 0.0.255.255   //普通acl

access-list standard CCNP
	permit/deny 10.1.1.0 0.0.0.255           //标准acl
```


```c

R1(config)#ip access-list standard R1-out
R1(config-std-nacl)#deny 10.1.1.1 

router eigrp 90
 distribute-list R1-in out
 network 0.0.0.0
 eigrp router-id 1.1.1.1

```

**此时R3无法ping通R2**

![[Pasted image 20260927165841.png]]

而ACL时从上往下开始匹配，如果没有匹配上的话就默认deny

![[Pasted image 20260927171701.png]]

所以ping没有在规则里的10.1.2.1的时候是被拒绝的

```

R1(config)#ip access-list standard R1-out
R1(config-std-nacl)#permit any

```

执行后才能ping通

**标准ACL是无法匹配掩码的，所以路由匹配的并不准确。**


不同的路由协议它的工作原理也不一样，因为EIGRP是触发时更新，但它的路由被阻断了所以其它路由并没有它的路由信息就不会留在路由表里。发现10.1.1.0/24不再出现在路由表中，并且发送更新和确认报文。

**我们删除R1出方向的distribute-list**

然后在R2的入方向配置
```
R2(config)#ip access-list standard R1-in
R2(config-std-nacl)#permit 192.168.1.0 0.0.0.255

router eigrp 90
 distribute-list R1-in in

```
