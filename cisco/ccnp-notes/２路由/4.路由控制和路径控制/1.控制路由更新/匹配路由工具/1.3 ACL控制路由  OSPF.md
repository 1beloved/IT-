
**OSPF（链路状态）**

- 同一区域内所有路由器的 LSDB 必须一致，所以 distribute-list 不能阻止 LSA 的泛洪。
- `distribute-list in` 过滤的是 SPF 计算出来的结果：这条路由不会装入**本地路由表**，但 LSDB 里还有，LSA 照样发给邻居。
- 所以它对**本地路由表是有影响的，只是对邻居没有影响**。邻居仍会认为可以经过你到达该网络，可能造成黑洞或次优路径。
- 想真正影响其他路由器，要在边界上做：ABR 上用 `area filter-list` 或 `area range ... not-advertise` 过滤 Type 3 LSA；ASBR 上在重分发时用 route-map 或 distribute-list 控制 Type 5 LSA。

**EIGRP / RIP（距离矢量）**

- `distribute-list in`：被过滤的路由不会被接受，EIGRP 的拓扑表里没有它，路由表里也没有，更不会再通告给别的邻居。
- `distribute-list out`：这条路由不会出现在发给邻居的更新里。对 EIGRP 来说，配置后会发出更新把它撤销，邻居收到后就把这条路由删除。

而OSPF特殊在于**通常情况下**它在distribute-in的**入方向是没有用的**。而且只会对路由表产生影响，对database没有任何影响。就是在database加载数据到RIB之间的一个操作。所以只能在R2的入方向进行控制。



```      R2
router ospf 110
 network 192.168.1.0 0.0.0.255 area 0
 network 192.168.2.0 0.0.0.255 area 0
 distribute-list R1-in in
```

但是有一种情况可以在出方向工作，就是在 `router ospf` 下配置 `distribute-list ... out`，只对**重分发**有效：在 ASBR 上过滤从其他协议**重分发进 OSPF 的外部路由**。

OSPF 里 `distribute-list out` 控制的是重分发这一步：

1. ASBR 从别的协议（比如 EIGRP）的路由表里拿到路由。
2. 重分发时先经过 distribute-list（或 route-map）的检查。
3. 通过检查的路由，才由 ASBR 生成 Type 5 LSA，放进自己的 LSDB 并泛洪出去。
4. 被过滤的路由根本没有生成 LSA，所以自己的 LSDB 和邻居的 LSDB 里都没有。

**它过滤的是"是否生成 LSA"，不是"是否发送已有的 LSA"，所以不会破坏 LSDB 一致的规则。**

**这些路由在 ASBR 上仍然存在**

- 被过滤的路由**仍留在 ASBR 的路由表**里（来源是 EIGRP 等原协议），只是**没有进入 OSPF**。
- 所以 ASBR 自己还能到达这些网络，OSPF 域里的其他路由器则不知道它们。

**和入方向的对比**

- 入方向：LSA 已经在 LSDB 里，只是不装入路由表，LSA 仍会继续泛洪。
- 出方向（重分发）：LSA 根本没生成，LSDB 里没有，也不会泛洪。

此时重分发路由让换回路由变为五类LSA,然后添加ACL禁止10.1.1.1。其它路由正常通过。

```

R1(config)#ip access-list standard CCNP?

R1(config-std-nacl)#deny 10.1.1.1

R1(config-std-nacl)#permit any
R1(config-std-nacl)#exit
R1(config)#router ospf 110
R1(config-router)#distribute-list CCNP ?
  in   Filter incoming routing updates
  out  Filter outgoing routing updates

R1(config-router)#distribute-list CCNP out

```
