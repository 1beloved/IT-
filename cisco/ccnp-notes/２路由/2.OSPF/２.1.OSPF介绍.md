**Router-id**
**如果没有手动配置就会自动选举，首先选取环回地址中大的，如果没有环回地址就选取接口地址最大的**
- **身份唯一标识**：在OSPF域中，Router-ID是每台路由器的“身份证号”。所有LSA（链路状态通告）在传播时，都会通过携带的Router-ID来标明“这条链路状态信息是哪台路由器产生的”。
    
- **邻居建立**：在OSPF邻居关系（邻接关系）建立过程中，路由器会交换DD（数据库描述）报文，其中就包含各自的Router-ID，用来确认对方身份。
    
- **选举依据**：在以太网等广播型网络中，选举DR（指定路由器）和BDR（备份指定路由器）时，如果**端口优先级相同**，**Router-ID最大的路由器**会被选为DR。

```
S1(config)#router ospf 1
S1(config-router)#router-id 1.1.1.1

```

> **区域**（Area）就是一组接口的集合。

不是基于路由器，也不是基于路由，而是**基于接口**。你把哪些接口划分到同一个区域里，这些接口所属的路由器就在同一个区域里。**所以一台路由器可以同时属于多个区域**，只要它的不同接口配置了不同的区域号。
1. **必须有一个 Area 0（骨干区域）**：所有其他区域必须直接或间接（通过虚拟链路）连接到 Area 0。 
2. **非骨干区域不能直接互通**：Area 1 和 Area 2 不能直接交换路由，必须通过 Area 0 中转。

LSA也只在自己的区域泛洪
```
router ospf 1
 network 10.1.1.0 0.0.0.255 area 0
 network 10.2.2.0 0.0.0.255 area 0
 
 interface g0/0
 ip ospf 1 area 0

interface g0/1
 ip ospf 1 area 0
```
### 规则一：必须有且只有一个 Area 0（骨干区域）

- Area 0 是整个OSPF域的**中枢神经系统**。
    
- 所有非骨干区域都必须**直接或间接**连接到Area 0。
    

### 规则二：非骨干区域不能直接互通

- Area 1 和 Area 2 之间**不能直接交换路由**。
    
- Area 1 → Area 0 → Area 2，必须通过骨干中转。
    
- **唯一例外**：配置**虚拟链路（Virtual Link）**，逻辑上穿过Area 0连接。

## 🧩 区域里的角色分工（四类路由器）

|角色|定义|核心职责|
|---|---|---|
|**IRR（内部路由器）**|所有接口都在同一个区域|只维护本区域LSDB，只计算本区域路由|
|**ABR（区域边界路由器）**|同时连接Area 0和另一个区域|**核心角色**：维护多个区域LSDB，做区域间路由汇总和传递|
|**ASBR（自治系统边界路由器）**|连接OSPF域和其他路由协议或外部网络|将外部路由重分发进OSPF，产生Type 5 LSA|
|**骨干路由器**|至少有一个接口在Area 0|Area 0内的所有路由器 + 所有ABR|

## 📦 区域与LSA（链路状态通告）的关系

不同区域类型决定了哪些LSA可以在区域内传播：

| LSA类型      | 名称               | 传播范围                          |
| ---------- | ---------------- | ----------------------------- |
| **Type 1** | Router LSA       | 只在**本区域**内传播（每台路由器产生一条）       |
| **Type 2** | Network LSA      | 只在**本区域**内传播（由DR产生，描述广播链路）    |
| **Type 3** | Summary LSA      | **跨区域传播**（由ABR产生，描述其他区域的路由）   |
| **Type 4** | ASBR Summary LSA | **跨区域传播**（由ABR产生，描述ASBR的位置）   |
| **Type 5** | External LSA     | **整个OSPF域**传播（由ASBR产生，描述外部路由） |

**关键结论**：

- Type 1和Type 2**被锁在区域内** → 区域隔离了拓扑细节。
    
- Type 3/4/5可以跨区域 → 区域间只传递“汇总后的路由”，不传递拓扑。

## 🔧 特殊区域类型（CCNP考试重点）

为了进一步优化资源，OSPF定义了三种特殊区域：

|区域类型|允许进入的LSA|禁止进入的LSA|替代方式|
|---|---|---|---|
|**Stub（末梢区域）**|Type 1、2、3|Type 4、5（外部路由）|ABR自动生成一条**默认路由（0.0.0.0/0）**|
|**Totally Stub（完全末梢）**|Type 1、2|Type 3、4、5（连区域间路由都禁止）|ABR自动生成一条**默认路由**，覆盖所有外部和区域间目的地|
|**NSSA（非纯末梢区域）**|Type 1、2、3、7|Type 5（外部路由）|本区域的ASBR产生**Type 7 LSA**，由ABR转换为Type 5|

### 为什么需要特殊区域？

- **Stub区域**：边缘区域不需要访问外部网络（如分支办公室），用一条默认路由代替所有外部路由，极大减小路由表和LSDB。
    
- **Totally Stub**：更极端，连区域间路由都不需要，完全靠默认路由。
    
- **NSSA**：边缘区域有自己的外部出口（如连接另一个ISP），但不想接收骨干区域传来的外部路由。

## 🔗 虚拟链路（Virtual Link）

### 是什么？

当非骨干区域**物理上无法直接连接到Area 0**时，可以通过虚拟链路**逻辑上**连接到Area 0。

### 典型场景

text

Area 2 → Area 1（中转） → Area 0

Area 2 不直连Area 0，需要通过Area 1“穿”过去。

### 配置命令

text

router ospf 1
 area 1 virtual-link 10.0.0.1   # area 1是中转区域，10.0.0.1是目标ABR的Router ID

### ⚠️ 注意事项

- 虚拟链路只能**穿过一个普通区域**（不能穿过Stub/Totally Stub/NSSA）。
    
- 中转区域必须有完整的路由信息（不能是特殊区域）。
    
- 虚拟链路应视为**临时方案**，生产环境中尽量通过物理连接解决。

## LSA
它确实不直接传递“路由信息”（比如去往某个网络下一跳是谁），而是传递“链路状态信息”——也就是一张**网络拓扑的拼图碎片**。

这张“拼图”在OSPF（开放式最短路径优先）协议中，通过一套精巧的机制，最终拼出了完整的网络地图，并计算出最优路径。整个过程可以分为三个环环相扣的步骤。

### 第一步：传递“拼图碎片”（LSA的生成与泛洪）

每台OSPF路由器都会为自己直连的网络生成一个或多个LSA，这个LSA就像一个“碎片”，详细描述了它自己的链路状态

- **信息内容**：包括自己的路由器ID、直连的接口IP、接口的开销（Cost）、以及邻居路由器的ID等
    
- **可靠传递**：路由器会将这个LSA“泛洪（Flooding）”给所有邻居。邻居收到后，会复制一份到自己的数据库中，再继续传给它的其他邻居，直到这个区域（Area）内的所有路由器都收到。这个过程有确认和重传机制（如LS Ack）来保证可靠性
    

### 第二步：拼出“全网地图”（构建链路状态数据库LSDB）

每台路由器收到所有LSA后，并不直接使用，而是将它们全部存放在一个 **链路状态数据库（LSDB，Link State Database）** 中。这个数据库，就是这张“拼图”的完整形态——一份精确的网络拓扑图。

由于所有路由器接收到的LSA集合最终是相同的，所以**每台路由器都拥有了一张完全一致的网络地图。比如，Router LSA（Type 1）描述了路由器自己的连接，而Network LSA（Type 2）则描述了广播网段上所有路由器的关系。这些不同类型的LSA共同构成了完整的拓扑信息。

### 第三步：每个人自己“导航”（运行SPF算法计算路由）

这是最关键的一步。有了地图之后，**每台路由器独立地**在这张地图上运行 **SPF（最短路径优先）算法**（也叫Dijkstra算法）。

1. **计算最优路径**：路由器以自己为“起点”，通过SPF算法计算出到达地图上每一个其他节点的最短路径，形成一棵以自己为根的 **最短路径树（SPT，Shortest Path Tree）
2. **生成路由表**：最后，路由器根据这棵SPT，将最优路径转换成具体的路由条目，写入路由表

| 类型         | 名称                | 作用                            | 主要传播范围                |
| ---------- | ----------------- | ----------------------------- | --------------------- |
| **Type 1** | Router LSA        | 描述**本区域内路由器及其链路**             | Area 内                |
| **Type 2** | Network LSA       | 描述**多路访问网络（如以太网）以及连接的路由器**    | Area 内                |
| **Type 3** | Summary LSA       | **ABR**把其他 Area 的网络信息引入本 Area | Area 间                |
| **Type 4** | ASBR Summary LSA  | 告诉其他 Area：**ASBR 在哪里**        | Area 间                |
| **Type 5** | AS External LSA   | **ASBR**把 OSPF 外部路由引入 OSPF    | 整个 OSPF 域，除 Stub Area |
| **Type 7** | NSSA External LSA | NSSA 中的 ASBR 发布外部路由           | NSSA 内                |

注意：**严格来说 OSPF 不只有六种 LSA 类型**，还有 Type 6、8、9、10、11 等；但在 CCNP 学习中，最核心、最常考的就是 **1、2、3、4、5、7**。

### 你可以先这样理解整个逻辑

假设：

```
             Area 0
        ┌──────┴──────┐
       ABR           ABR
        │
      Area 1
     ┌──┴──┐
    R1     R2
```

**Area 1 内部：**

- R1/R2 描述自己的链路 → **Type 1**
- 如果 R1、R2 接在同一个 Ethernet 网络 → DR 产生 **Type 2**

**Area 0 和 Area 1 之间：**

- ABR 告诉 Area 1：“Area 0 有这些网段” → **Type 3**
- 如果 Area 0 里有 ASBR，ABR 告诉 Area 1：“那个 ASBR 在那里” → **Type 4**

**外部网络：**

```
Internet
   │
 ASBR
   │
 OSPF
```

ASBR 把外部路由引进来：

→ **Type 5**

如果 ASBR 位于 **NSSA**：

→ **Type 7**

### 最重要的记忆口诀

> **1自己，2网段，3跨区网，4找ASBR，5外部，7 NSSA外部**

尤其要把 **Type 3 / 4 / 5** 区分开：

```
Type 3：其他 Area 的“网络”
Type 4：其他 Area 的“ASBR”
Type 5：OSPF 外面的“外部路由”
```



## Hello报文不匹配
Hello条件不匹配导致邻居关系无法建立：当Hello报文中的关键参数不一致时，路由器不会建立邻居关系。
- Area ID不一致：如果两台路由器的区域ID不同，则不会建立邻居关系。
- Hello/Dead Time不一致：Hello报文的发送间隔和死亡时间必须一致，否则会导致邻居关系无法建立或频繁中断。
- 认证参数不一致：包括认证类型（如MD5）和认证数据（口令）必须匹配，否则无法建立邻居关系。
- Network Mask不一致：在广播网络中，子网掩码必须一致，否则不建立邻居关系。
- Stub/NSSA标志不一致：特殊区域标志（如Stub或NSSA）必须一致，否则无法建立邻居关系。
- Router ID重复：如果Router ID重复，会导致邻居关系异常。
- Hello报文中的关键字段：包括DR、BDR、Active Neighbor、Priority等，在邻居建立过程中逐步填充和确认。
- 双向可见性：当双方确认信息后，Hello报文的邻居列表中会包含对端的Router ID，表示双向可见。
