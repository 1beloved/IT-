

## 一、基本配置

```cisco
ip route 0.0.0.0 0.0.0.0 203.0.113.1

router ospf 1
 default-information originate
```

两步缺一不可：

1. 静态默认路由让这台路由器自己有出口
2. `default-information originate` 让它向 OSPF 区域内通告 0.0.0.0/0

这台路由器随之成为 **ASBR**，因为它把外部路由信息引入了 OSPF。

## 二、为什么不能用 `redistribute static`

OSPF 里 `redistribute static subnets` **不会把默认路由重分发进来**，OSPF 对 0.0.0.0/0 做了特殊处理，必须用 `default-information originate` 显式产生。

这和 EIGRP 不同：EIGRP 里 `redistribute static` 可以带着默认路由一起发出去。

## 三、命令选项

```cisco
default-information originate [always] [metric 值] [metric-type {1|2}] [route-map 名称]
```

|选项|作用|
|---|---|
|不带 `always`|本机路由表里**必须已经有默认路由**才通告，默认路由消失就撤销|
|`always`|无论本机有没有默认路由都通告，常用于无条件下发|
|`metric`|指定默认路由的 metric，不写则默认为 **1**|
|`metric-type`|外部类型，默认是 **Type 2（E2）**|
|`route-map`|加条件，route-map 匹配成功时才通告，常配合 `match ip address` 或跟踪状态使用|

要点：

- 默认路由的 metric 默认是 1，和普通重分发路由的默认 20 不同，这是考试易错点
- 不带 `always` 时，触发条件的默认路由**不能是 OSPF 自己学到的**，必须是静态、BGP 或其他非 OSPF 来源

## 四、通告出去的是什么 LSA

| 区域类型                  | 默认路由的承载方式                                  |
| --------------------- | ------------------------------------------ |
| 普通区域                  | Type 5（AS External LSA），在整个 OSPF 域内泛洪      |
| NSSA 区域               | Type 7（NSSA External LSA），经 ABR 转换为 Type 5 |
| Stub / Totally Stubby | 不允许 Type 5，由 **ABR 自动**向区域内产生 Type 3 默认路由  |

跨区域时还要有 **Type 4（ASBR Summary LSA）**，告诉其他区域"ASBR 在哪里"，这样别的区域的路由器才能到达 ASBR 并使用这条外部路由。

## 五、E1 与 E2 的区别

| |E2（默认）|E1|
|---|---|---|
|metric 计算|全程固定，只用起始 metric|起始 metric 加上到 ASBR 的内部开销|
|选路影响|到 ASBR 的路径远近不影响默认路由的 metric|距离 ASBR 越近 metric 越小|
|适用场景|单个出口|**多个出口**，需要就近选择|

多个边界路由器都下发默认路由时，用 E1 能让内部路由器自动选离自己近的出口：

```cisco
default-information originate metric 10 metric-type 1
```

用 E2 的话，多台路由器下发相同 metric，内部路由器会比较到各 ASBR 的内部开销来选，但 metric 本身不累加，逻辑和 E1 不同。同类型相同 metric 时，E2 才会比较 forward metric（到 ASBR 的开销）。

## 六、不同区域类型下的做法

### 1. 普通区域

直接在 ASBR 上配置，如第一节。

### 2. Stub / Totally Stubby 区域

Type 5 进不来，所以**不需要也不能**在区域内路由器上手工通告：

```cisco
router ospf 1
 area 1 stub                  ! 区域内所有路由器都要配
 area 1 stub no-summary       ! 仅 ABR 配，变成 Totally Stubby
```

ABR 会自动向区域内注入默认路由（Type 3），区域内路由器靠这条默认路由出去。ASBR 本身不能放在 Stub 区域里。

### 3. NSSA 区域

NSSA 里允许有 ASBR，外部路由以 Type 7 引入。默认路由有两种方式产生：

```cisco
! 在 NSSA 内的 ASBR 上
router ospf 1
 area 1 nssa
 default-information originate         ! 产生 Type 7 默认路由

! 在 ABR 上，向 NSSA 内注入默认路由
router ospf 1
 area 1 nssa default-information-originate
```

注意：NSSA 的 ABR 默认**不会**自动下发默认路由，需要手工配 `area x nssa default-information-originate`（Totally NSSA 用 `no-summary` 才会自动注入）。

## 七、结合 IP SLA 做有条件通告

静态默认路由只要出接口不 down 就一直存在，对端故障时 OSPF 仍然继续通告，内部流量被引向黑洞。用 track 绑定静态路由，让它故障时消失，OSPF 随之自动撤销：

```cisco
ip sla 1
 icmp-echo 203.0.113.1 source-interface g0/0
 frequency 5
ip sla schedule 1 life forever start-time now

track 1 ip sla 1 reachability

ip route 0.0.0.0 0.0.0.0 203.0.113.1 track 1

router ospf 1
 default-information originate          ! 不带 always
```

关键：这里**不能带 `always`**。带了 `always` 的话，即使静态默认路由因 track Down 而消失，OSPF 依然会通告，条件就失效了。

## 八、验证

在 ASBR 上：

```cisco
show ip ospf                      ! 看到 "It is an autonomous system boundary router"
show ip route 0.0.0.0             ! 本机默认路由存在（不带 always 时必须有）
show ip ospf database external    ! 看自己产生的 Type 5 LSA，Link State ID 为 0.0.0.0
```

在内部路由器上：

```cisco
show ip route ospf
```

期望看到：

```text
O*E2  0.0.0.0/0 [110/1] via 10.0.12.1, 00:05:12, GigabitEthernet0/0
```

读法：

- `O*E2`：OSPF 外部类型 2 的默认路由（`*` 表示候选默认路由）
- `[110/1]`：AD 110，metric 1，印证第三节说的默认 metric 是 1

## 九、排错

内部路由器收不到默认路由，按顺序查：

1. ASBR 上有没有 `default-information originate`
2. 不带 `always` 时，ASBR 本机路由表里是不是真的有默认路由（静态路由可能因下一跳不可达或 track Down 没装进去）
3. 区域类型是不是 Stub，Stub 区域里 Type 5 进不来，需要靠 ABR 自动下发
4. 跨区域时，Type 4 有没有到达，其他区域能否到达 ASBR
5. 区域边界上有没有被过滤（distribute-list、LSA 过滤）
6. NSSA 的 ABR 有没有配 `area x nssa default-information-originate`

## 十、速记

|要点|结论|
|---|---|
|通告默认路由的命令|`default-information originate`|
|`redistribute static` 能否带默认路由|不能|
|默认 metric / 类型|1 / E2|
|通告前提|本机有默认路由，或配 `always`|
|承载 LSA|Type 5（普通），Type 7（NSSA）|
|Stub 区域默认路由|ABR 自动下发 Type 3|
|NSSA 的 ABR|需手工 `area x nssa default-information-originate`|
|备份切换|静态路由配 track，且不要带 `always`|
