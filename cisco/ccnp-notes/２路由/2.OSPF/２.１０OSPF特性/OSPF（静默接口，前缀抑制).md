# 一、浮动动态路由

## 1.1 为什么需要浮动动态路由

**典型场景：单出口路由器的单点故障**

```
LAN ─── R1 ─── R2 ─── Internet
                  ↑
                单点故障
```

R2 一旦故障，整个内部网络都无法访问 Internet。

**解决方案：双出口 + 动态主备**

```
                    ┌── R2 ─── ISP
                    │
LAN ─── R1 ─────────┤
                    │
                    └── R3 ─── ISP
```

利用 OSPF 发布两条默认路由，实现**动态主备**。核心思路：通过 OSPF 实现类似浮动静态路由的效果。

---

## 1.2 核心命令

两台出口路由器都发布默认路由：

```cisco
router ospf 110
 default-information originate always
```

> 作用：把自己的默认路由转发到 OSPF 中，这样就不需要添加重定向静态路由了。

课程同时涉及：

```cisco
redistribute static
```

R2/R3 都向 OSPF 域发布：

```
O*E2 0.0.0.0/0
```

这样内部路由器就拥有两个去 Internet 的路径。

---

## 1.3 通过 OSPF Cost 实现主备

**拓扑：**

```
             R2
            /  \
           /    \ ISP
          /
LAN ─── R1
          \
           \
            R3 ─── ISP
```

R2 和 R3 都发布 `0.0.0.0/0`。

**默认情况下：**

```
R2：OSPF Cost = 1
R3：OSPF Cost = 1
```

两条路径相同，无法形成主备。

**修改 R2 的 metric：**

```cisco
default-information originate always metric 5
```

**结果：**

```
R3 → default route → metric 1
R2 → default route → metric 5
```

**正常状态：**

```
R1
├── R3 → ISP   metric 1   ← 主路径
└── R2 → ISP   metric 5   ← 备用路径
```

**R3 故障时：**

```
R1
└── R2 → ISP   metric 5   ← 自动切换
```

课程明确将这种方式称为**浮动动态路由**。

---

## 1.4 浮动静态路由 vs 浮动动态路由

| 类型 | 控制什么 | 目的 |
|------|----------|------|
| 浮动静态路由 | AD | 主备 |
| 浮动动态路由 | OSPF Cost/Metric | 主备 |

**一句话记忆：**

> 浮动静态看 AD，浮动动态看 Metric。

# 二、Passive Interface（静默接口）

## 2.1 核心概念

> **不发送/不接收 OSPF Hello，但接口所在网段仍然可以参与 OSPF 路由计算。**

- Cisco 叫：`passive interface`
- 华为叫：`静默接口`

本质功能相同。

---

## 2.2 为什么需要 Passive Interface

**场景：**

```
             OSPF
R1 ───────────────── R2
 |
 |
 PC
```

R1 的 G0/2 连接 PC，PC 不可能和 R1 建立 OSPF 邻居。

如果 R1 仍然在这个接口发送 Hello：

```
R1 ── Hello ──→ PC
R1 ── Hello ──→ PC
R1 ── Hello ──→ PC
```

没有意义。

**配置 Passive Interface 后：**

```
R1 G0/2 ─── PC
      ✕ Hello
      ✕ Neighbor
```

但是：

```
192.168.1.0/24
        ↓
仍然进入 OSPF
        ↓
其他路由器仍然可以学习
```

**最重要的理解：**

> **Passive ≠ 不宣告。**
> 而是：**宣告网段，但不建立邻居。**

---

## 2.3 实验拓扑与配置逻辑

**拓扑：**

```
             OSPF
        ┌──────────────┐
        │              │
       R1 ─────────── R2
        │
        │ G0/2
        │
        PC
   192.168.1.0/24
```

R1：G0/2 = 14.1.1.1/24，该网段 `14.1.1.0/24` 需要被 OSPF 学习，但 PC ≠ OSPF Router，因此 G0/2 设置为 Passive。

**配置：**

```cisco
router ospf 110
 network 14.1.1.0 0.0.0.255 area 0
 passive-interface g0/2
```

**最终效果：**

```
14.1.1.0/24
      ↓
进入 OSPF
      ↓
其他路由器可以学习
```

同时：

```
G0/2
 ↓
不发送 Hello
 ↓
不建立 OSPF Neighbor
```

---

## 2.4 三个考试关键词

看到题目出现下面这种描述，基本就应该想到 Passive Interface：

1. **连接 PC / Server**
   ```
   Router ─── PC
   ```

2. **不需要建立 OSPF 邻居**
   ```
   需要路由
   不需要 Neighbor
   ```

3. **仍然需要发布该网段**
   ```
   网段要进入 OSPF
   ```

> **Passive Interface = 保留路由发布 + 禁止邻居建立。**

# 三、Prefix Suppression（前缀抑制）

## 3.1 核心概念与目的

**核心目的：**

> **抑制 OSPF 设备之间直连接口所在网段的路由通告。**

**示例：**

```
       12.1.1.0/24
R1 ───────────────── R2
```

正常情况下，OSPF 会让设备学习 `12.1.1.0/24`。但很多时候：

> 我真正需要的是"到达 R1/R2"，而不是这个设备之间的传输网段。

因此可以使用 Prefix Suppression 来减少不必要的网段路由。

**配置：**

```cisco
router ospf 10
 prefix-suppression
```

---

## 3.2 实验拓扑与 IP 地址规划

**拓扑：**

```
             R2
           /    \
          /      \
        R1        R4
          \      /
           \    /
             R3
```

**连接关系：**

```
R1 ─── R2
│       │
│       │
R3 ─── R4
```

**具体链路：**

```
R1-R2：12.1.1.0/24
R1-R3：13.1.1.0/24
R2-R4：24.1.1.0/24
R3-R4：34.1.1.0/24
```

**终端：**

```
PC5 ─── R1
PC6 ─── R4
```

PC 网段：

```
192.168.1.0/24
192.168.2.0/24
```

**IP 地址表：**

| 设备 | 接口 | IP |
|------|------|-----|
| R1 | Lo0 | 1.1.1.1/32 |
| R2 | Lo0 | 2.2.2.2/32 |
| R3 | Lo0 | 3.3.3.3/32 |
| R4 | Lo0 | 4.4.4.4/32 |
| R1 | E0/0 | 12.1.1.1/24 |
| R2 | E0/0 | 12.1.1.2/24 |
| R1 | E0/1 | 13.1.1.1/24 |
| R3 | E0/0 | 13.1.1.3/24 |
| R2 | E0/1 | 24.1.1.2/24 |
| R4 | E0/0 | 24.1.1.4/24 |
| R3 | E0/1 | 34.1.1.3/24 |
| R4 | E0/1 | 34.1.1.4/24 |
| R1 | E0/2 | 192.168.1.1/24 |
| R4 | E0/2 | 192.168.2.1/24 |

> Loopback 使用 `/32`，用于设备标识。

---

## 3.3 基础配置

课程实验为简化操作：

```cisco
router ospf 110
 network 0.0.0.0 255.255.255.255 area 0
```

> 含义：把所有接口加入 Area 0。
> 课程特别提醒：实际工程中应该精确宣告网络，而不是直接使用 `0.0.0.0 255.255.255.255`。

---

## 3.4 为什么需要 Loopback

每台路由器配置：

```
R1 → 1.1.1.1/32
R2 → 2.2.2.2/32
R3 → 3.3.3.3/32
R4 → 4.4.4.4/32
```

```cisco
interface loopback 0
 ip address 1.1.1.1 255.255.255.255
```

**作用：**

> 给设备提供一个稳定的设备级标识，即使某条物理链路故障，也可以通过其他路径访问该地址。

---

## 3.5 配置前后的区别

**配置前，路由表可能出现大量互联链路：**

```
12.1.1.0/24
13.1.1.0/24
24.1.1.0/24
34.1.1.0/24
192.168.1.0/24
192.168.2.0/24
```

实际上访问 PC（PC5 → PC6），最重要的是 `192.168.2.0/24`，而不是 `24.1.1.0/24`、`34.1.1.0/24`。

> 路由器最需要的是目标 IP 所属网段的精确路由。

---

## 3.6 核心配置命令

```cisco
router ospf 10
 prefix-suppression
```

**配置以后：**

```
互联链路网段
      ↓
    抑制
      ↓
减少不必要的路由
```

**但要注意保留：**

```
Loopback
   ↓
保留

PC网段
   ↓
保留
```

课程中明确指出：

- Loopback 路由保留
- Passive-interface 连接的 PC 网段需要保留
- 不能错误地把终端网段也抑制掉

---

## 3.7 最容易出现的坑

**场景：**

```
PC5 ─ R1 ───── R4 ─ PC6
```

PC6：`192.168.2.0/24`

如果把这个网段也错误抑制：

```
192.168.2.0/24
       ↓
    被抑制
       ↓
R1 不知道怎么去 PC6
```

结果：

```
PC5 ──X── PC6
```

**考试中看到：**

> 配置 Prefix Suppression 后某个终端网段不可达

**首先检查：**

> 终端网段是不是被错误抑制？

课程实验也明确指出，错误抑制 PC 网段会导致 `192.168.2.0/24` 路由缺失，从而使 PC5 与 PC6 通信中断。

---

## 3.8 底层现象：/24 → /32

课程中给出的重要实验现象：

**正常：**

```
1.2.1.0/24
```

**经过 Prefix Suppression 后：**

```
1.2.1.1/32
```

即：

```
/24
 ↓
/32
```

本质上：

> 将直连网络的信息处理成主机路由，使 OSPF 不再按照普通网段路由进行计算。

例如课程实验中的表现：

```
R2 → 1.2.1.2/32
R3 → 1.3.1.3/32
R4 → 1.4.1.4/32
```

而不是完整的：

```
1.2.1.0/24
1.3.1.0/24
1.4.1.0/24
```

# 四、Passive Interface vs Prefix Suppression

## 4.1 对比表

| 对比 | Passive Interface | Prefix Suppression |
|------|-------------------|---------------------|
| 核心目的 | 不建立邻居 | 减少不必要的前缀 |
| Hello | 不发送 | 重点不是禁止 Hello |
| Neighbor | 不建立 | 可以正常建立 |
| 网段是否参与 OSPF | 是 | 根据抑制对象处理 |
| 常见场景 | PC、Server | OSPF 路由器互联链路 |
| 典型命令 | `passive-interface` | `prefix-suppression` |

## 4.2 一句话记忆

```
Passive Interface
= 不要 Neighbor，但我要这个网段

Prefix Suppression
= Neighbor 可以存在，但这个前缀没必要到处传播
```

# 五、LSDB → SPF → RIB 的关系

## 5.1 为什么 show ip ospf database 基本没变

**实验现象：**

```
show ip ospf database
    ↓
基本没明显变化

show ip route
    ↓
某些 OSPF 路由消失
```

**原因：**

> Prefix Suppression 主要影响的是"前缀是否进入其他路由器的路由计算/路由表"，而不是简单地把整个 OSPF 拓扑信息从 LSDB 删除。

**三层关系：**

```
              OSPF
               │
        ┌──────┴──────┐
        ↓             ↓
     Topology       Prefix
        │             │
     保留            抑制
        │             │
        ↓             ↓
     SPF计算       不再形成对应路由
        │
        ↓
    show ip route
```

**举例：**

```
R1 -------- R2 -------- R3
```

R1-R2：`10.1.12.0/24`

R2-R3：`10.1.23.0/24`

正常情况下 R3 可能看到：

```
O 10.1.12.0/24 via 10.1.23.2
```

开启 Prefix Suppression 后：

```
R3# show ip route

O 10.1.12.0/24
       ↓
     消失
```

但是 R3 仍然需要知道：

```
R1 ---- R2 ---- R3
```

否则它怎么知道去 R1 后面的业务网络应该 `R3 → R2 → R1`。

所以 **LSDB 中描述 R1/R2 拓扑的内容仍然需要存在**。

---

## 5.2 LSA 不等于路由

这是 OSPF 学习中非常值得建立的思维：

**LSA 是：**

> 我把我知道的链路状态/前缀信息告诉 OSPF 域。

**处理流程：**

```
LSA
 ↓
LSDB
 ↓
SPF算法
 ↓
最优路径
 ↓
RIB
 ↓
show ip route
```

因此：

- `show ip ospf database` 看到的是 **LSDB 里的 LSA 信息**
- `show ip route` 看到的是 **最终进入 RIB 的路由**

两者本来就不是一回事。

---

## 5.3 实验验证方法

如果你发现 `show ip ospf database` 里面的**具体 LSA 内容其实发生了一些变化，只是 LSA 的数量/类型看起来没变化**，这也是完全可能的。

因为 Prefix Suppression 并不一定意味着：

```
LSA直接消失
```

而可能是：

```
LSA仍然存在
        ↓
其中某些 Prefix 被抑制
        ↓
SPF计算时不再把这些Prefix作为普通可达网络安装
        ↓
show ip route 中消失
```

**验证步骤：**

实验前：

```cisco
show ip route ospf
show ip ospf database router
```

开启 Prefix Suppression 后：

```cisco
show ip route ospf
show ip ospf database router
```

**重点观察：**

```
LSDB：
R1/R2之间的拓扑关系还在吗？
        ↓
如果还在 → OSPF仍然知道R1和R2怎么连接

RIB：
10.1.12.0/24还在吗？
        ↓
如果消失 → 这个前缀被抑制
```

**一句话总结：**

> `show ip ospf database` 看的是 OSPF 的"地图"，`show ip route` 看的是根据这张地图最终得到的"导航路线"。Prefix Suppression 的目的不是把地图上的道路删掉，而是让某些道路编号/目的前缀不再作为独立目的地出现在路由表里。

# 六、CCNP 必背总结表

```
┌──────────────────────────────────────┐
│          OSPF 特性核心记忆           │
├──────────────────────────────────────┤
│ 浮动动态路由                         │
│ → 利用 OSPF Metric 实现主备          │
│ → Metric 小的优先                    │
│ → 故障后自动切换                     │
├──────────────────────────────────────┤
│ Passive Interface                    │
│ → 不发送 Hello                       │
│ → 不建立 Neighbor                    │
│ → 网段仍参与 OSPF                    │
│ → 常用于 PC / Server                 │
├──────────────────────────────────────┤
│ Prefix Suppression                   │
│ → 抑制不必要的直连前缀               │
│ → 减少路由表中的无用网段             │
│ → Loopback 保留                      │
│ → 终端网段不能错误抑制               │
│ → 实验中可表现为 /24 → /32           │
└──────────────────────────────────────┘
```
