

> 核心逻辑链：**网络类型 → 是否选 DR/BDR → 邻居状态 → LSA 泛洪方式 → 命令验证**
> 
> OSPF 网络类型决定了接口上如何建立邻居，以及是否进行 DR/BDR 选举。课程重点是 **Broadcast ↔ P2P**。

---

## 一、四种 OSPF 网络类型

|特征|Broadcast|P2P|NBMA|P2MP|
|---|---|---|---|---|
|多路访问|是|否|是|是|
|DR/BDR|有|无|有|无|
|典型场景|Ethernet|PPP / HDLC 串行链路|Frame Relay|特殊多点网络|
|学习重点|DR/BDR 选举|快速建立邻居|非广播|多点拆分|

### 判断方法

先问三个问题：

1. 链路是不是多路访问？是 → Broadcast / NBMA / P2MP
2. 是不是 Ethernet？是 → 默认 **Broadcast**，有 DR/BDR
3. 是不是 PPP / HDLC 点到点？是 → **P2P**，无 DR/BDR

---

## 二、Broadcast（广播型）

### 1. 特点

- Ethernet 接口默认被识别为 Broadcast，查看：
    
    ```cisco
    show ip ospf interface e0/0
    ! 关注：Network Type BROADCAST
    ```
    
- 多个路由器接在同一个二层网络，属于多路访问，需要选举 DR/BDR。
    
- 默认 Hello 10s，Dead 40s，Wait 40s。
    

### 2. 为什么需要 DR/BDR

如果所有路由器两两建立完整邻接，邻接数量会快速增长。引入 DR/BDR 后，普通路由器只与 DR/BDR 建立 FULL 邻接，从而**减少邻接数量和 LSA 泛洪规模**。

|角色|全称|说明|
|---|---|---|
|DR|Designated Router|指定路由器|
|BDR|Backup Designated Router|备份指定路由器|
|DROTHER|-|既不是 DR 也不是 BDR 的其他路由器|

### 3. 邻居状态变化

```text
2-WAY → DR/BDR 选举 → EXSTART → EXCHANGE → LOADING → FULL
```

实验中会观察到 `EXSTART/DR`、`2WAY/DROTHER` 等状态，用 `show ip ospf neighbor` 查看。

### 4. 只有两台路由器直连也会涉及 DR

只要接口的 OSPF 网络类型仍是 Broadcast，即使拓扑里只有 R1、R2 两台设备，OSPF 依然按广播网络处理，会走 DR/BDR 相关过程。

### 5. 实验：Ethernet 直连

```text
R1 E0/0 (12.1.1.1/24) ======== E0/0 (12.1.1.2/24) R2
```

两端接口都加入 OSPF process 110，Area 0，观察邻居状态和 DR/BDR 角色。

## 三、P2P（点到点）

### 1. 特点

- 链路上只有两个节点，**不需要选举 DR/BDR**。
- 邻居建立比 Broadcast 更快、更直接。
- 默认 Hello 10s，Dead 40s。

### 2. 验证

```cisco
show ip ospf interface     ! Network Type 显示 POINT_TO_POINT
show ip ospf neighbor      ! 状态为 FULL，不显示 DR/BDR
```

### 3. 把 Ethernet 手工改成 P2P

Ethernet 链路上如果实际只有两个 OSPF 邻居，可以手工改为 P2P，省去 DR/BDR 过程，加快邻居建立：

```cisco
interface e0/0
 ip ospf network point-to-point
```

注意：看到 Ethernet 不代表一定是 Broadcast，要看题目有没有手工修改网络类型。

---

## 四、串行链路：PPP 与 HDLC

串行链路属于点到点链路，在 OSPF 中通常对应 P2P。

### 1. 默认封装

|厂商|串行接口默认封装|
|---|---|
|Cisco|HDLC|
|Huawei|PPP|

### 2. 配置

```cisco
interface s0/0
 encapsulation ppp      ! 改为 PPP
```

```cisco
interface s0/0
 encapsulation hdlc     ! 改为 HDLC
```

### 3. 注意事项

- **两端封装必须一致**。PPP 与 HDLC 不匹配会导致接口状态异常、链路不通。
- PPP 是公有标准协议。
- PPP / HDLC 帧里**没有源/目的 MAC 地址**，抓包时不要按 Ethernet 帧的思路去看，数据直接进行三层封装。

### 4. 实验：Cisco 串行链路

```text
R1 S0/0 (12.1.1.1/24) ======== S0/0 (12.1.1.2/24) R2
```

R1：

```cisco
interface s0/0
 ip address 12.1.1.1 255.255.255.0
 encapsulation ppp
```

R2：

```cisco
interface s0/0
 ip address 12.1.1.2 255.255.255.0
 encapsulation ppp
```

验证：

```cisco
ping 12.1.1.2
show ip interface brief
```

## 五、易错点

1. **Ethernet 不一定是 Broadcast** 默认是 Broadcast，但手工配置 `ip ospf network point-to-point` 后就是 P2P。
    
2. **P2P 没有 DR/BDR** 看到 PPP、HDLC、Serial、Point-to-Point，优先想到无 DR/BDR，邻居状态直接是 FULL。
    
3. **Broadcast 有 DR/BDR** 看到 Ethernet、Broadcast、Multi-Access，优先想到 DR / BDR / DROTHER。
    
4. **`FULL/DR` 描述的是邻居的角色，不是自己的角色** 例如 R1 上显示 `Neighbor 2.2.2.2 FULL/DR`，`/DR` 表示邻居 2.2.2.2 是 DR，不代表 R1 是 DR。

## 六、速记

|看到|想到|
|---|---|
|Ethernet|默认 Broadcast → DR/BDR → 邻居显示 `FULL/DR`、`FULL/BDR`、`2WAY/DROTHER`|
|PPP / HDLC Serial|P2P → 无 DR/BDR → 邻居显示 `FULL`|

常用命令：

```cisco
show ip ospf interface       ! 看网络类型
show ip ospf neighbor        ! 看邻居状态
interface s0/0
 encapsulation ppp           ! Cisco 串口改 PPP
 encapsulation hdlc          ! Cisco 串口改 HDLC
```
