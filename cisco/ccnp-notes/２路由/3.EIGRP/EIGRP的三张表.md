##### 1. 邻居表(Neighbor Table)
通过 **Hello 报文**发现邻居，要求**双方 AS 号一致**。这里有个 EIGRP 的特点：**只需单向收到 Hello 即可建立邻居关系**，不像 OSPF 要求双向确认。所以可能出现“单向邻居”现象——A 认为 B 是邻居，但 B 不认为 A 是邻居。

- **Hello 间隔**：LAN 接口默认 **5 秒**
    
- **Hold Time**：默认 **15 秒**（3 倍 Hello 时间）
    
- 相比 OSPF 的 10 秒 Hello / 40 秒 Dead Timer，EIGRP 收敛更快

```
show ip eigrp neighbors
```
##### 2. 拓扑表(Topology Table)

拓扑表相当于 **OSPF 的 LSDB**，但有个关键区别：**它存储的是路由信息，而不是 LSA**。笔记里说它“比 OSPF 的 LSDB 更直观”，因为它直接列出目标网络和度量值。

通过 **Update 报文**交换路由信息。EIGRP 采用**触发更新和部分更新**机制，只传递变化的路由信息，而不是周期性全量发送。

**核心字段**

| 字段              | 全称                                 | 含义                   |
| --------------- | ---------------------------------- | -------------------- |
| **Destination** | 目标网络                               | 如 12.1.1.0/24        |
| **FD**          | Feasible Distance（可行距离）            | **本地路由器到目的网络的最小度量值** |
| **RD/AD**       | Reported/Advertised Distance（通告距离） | **邻居路由器到同一目的网络的度量值** |

**拓扑表存什么**

- **所有学习到的路由信息**，包括直连路由和从邻居学到的路由
    
- **不是只存最优路径**，而是保存完整信息供 DUAL 算法计算
    
- 当两条路径总开销相同时，等价路由都会出现在拓扑表里，最终同时加入路由表

```
show ip eigrp topology
```
##### 3. 路由表(Routing Table)
路由表是**最终产出**，是经过 DUAL 算法计算后，真正用于数据转发的路由决策表

从拓扑表中选择 **FD 值最小的最优路由**加入路由表。

**只将最优路径加入路由表，备份路径需满足特定条件才会被考虑。**
EIGRP 支持**非等价负载分担**，但需要满足**可行性条件（FC）**。当两条路径总开销相同时，会同时加入路由表，笔记里类比为“上班可选择不同路线，时间相同可任意选择”。

```
show ip route
```
