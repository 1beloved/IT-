这张图是 EIGRP 的**四大关键技术**总览，可以把它理解为 EIGRP 协议的“四根支柱”。下面结合你之前上传的笔记，逐条详细解释。

---

| 术语       | 英文                                              | 含义                                                        |
| -------- | ----------------------------------------------- | --------------------------------------------------------- |
| **后继**   | Successor                                       | 到达目的地的**最佳路径**的下一跳路由器。它被放入路由表，是当前使用的路径。                   |
| **可行后继** | Feasible Successor（FS）                          | 到达目的地的**备份路径**的下一跳路由器。它被放入拓扑表，满足可行条件，可随时接替后继。             |
| **可行距离** | Feasible Distance（FD）                           | 从本路由器到目的地的**最小 Metric 值**。即当前最佳路径的 Metric。                |
| **报告距离** | Reported Distance（RD）/（Advertised Distance, AD） | 邻居路由器到达目的地的 Metric 值。也叫**通告距离（Advertised Distance, AD）**。 |
| **可行条件** | Feasible Condition（FC）                          | 判断一个邻居能否成为可行后继的条件：**AD < FD**。                            |
| **拓扑表**  | Topology Table                                  | 存放所有到达目的地的路径信息，包括后继和可行后继。                                 |
| **被动状态** | Passive State                                   | 路由处于稳定状态，有后继，没有正在进行的扩散计算。                                 |
| **活动状态** | Active State                                    | 路由丢失后继，正在向邻居发送 Query，等待 Reply，进行扩散计算。                     |

## 一、邻居发现协议

**图中原文：** 使用 Hello 包发现邻居，并动态地获知其直连的网络中的其他路由器。

**详细解释：**

EIGRP 不依赖手动配置邻居，而是通过 **Hello 报文**自动发现同一网段上的其他 EIGRP 路由器。

- **目的地址**：组播 `224.0.0.10`
- **hello time**：LAN 接口默认每 **5 秒**一次，如果高速链路>1.544M那么为5秒,反之60秒
- **Hold Time**：默认 **15 秒**（3 倍 Hello 时间），超时未收到 Hello 就认为邻居失效
- **建立条件**：双方 **AS 号必须一致**,就是**router eigrp number的number**，AS 号信息就携带在 Hello 报文中
- **关键特点**：EIGRP **只需单向收到 Hello 即可建立邻居关系**，不像 OSPF 要求双向确认。因此可能出现“单向邻居”现象——A 认为 B 是邻居，但 B 不认为 A 是邻居
- **与 OSPF 的区别**：不需要 DBD 报文交换，不需要 DR/BDR 选举，建立速度极快

**验证命令：**
```
show ip eigrp neighbors
debug eigrp packets hello
```

## 二、可靠传输协议（RTP）

**图中原文：** 确保 EIGRP 分组按顺序以可靠的方式传输给所有邻居。

**详细解释：**

EIGRP 报文直接封装在 IP 中（协议号 **88**），没有 TCP/UDP 可用，所以思科设计了 **RTP（Reliable Transport Protocol）** 来保证可靠性。注意：这个 RTP 和音视频的“实时传输协议”只是缩写相同，完全是两回事。

**核心机制——按报文类型区别对待：**

| 报文类型       | 是否需要确认 | 传输方式          |
| :--------- | :----- | :------------ |
| **Hello**  | 不需要    | 组播 224.0.0.10 |
| **Update** | 需要     | 组播/单播         |
| **Query**  | 需要     | 组播/单播         |
| **Reply**  | 需要     | 单播            |
| **ACK**    | 不需要    | 单播（Hello 的变种） |

**可靠传输怎么实现：**

1. 发送方给需要确认的报文分配**序列号**，如 `Sequence:8`
2. 接收方回 **ACK**，携带 `Acknowledge:8`，表示“第 8 号收到了”
3. 发送方收到确认才继续发下一个；**超时未确认就重传**
4. 重传有上限，笔记中写的是**最多 16 次**，超过就重置邻居关系

**关键理解点：**
- **ACK 不是独立报文类型，而是 Hello 的变种**。抓包里看到 `Hello(Ack)`，就是它在承担确认功能。普通 Hello 的 Acknowledge 字段为 0，确认 Hello 的 Acknowledge 字段填被确认报文的序列号。
- RTP 类似 TCP 的可靠传输，但**实现更轻量**：更像停等协议（前一个确认才发下一个），而不是 TCP 的滑动窗口。
- 还有**条件接收模式（CR 模式）**：当邻居接收队列满时，发送方改用单播按顺序补发，防止乱序。

**验证命令：**
```
debug eigrp packets
```

## 三、DUAL 有限状态机

**图中原文：** 选择最低的度量值和无环的路径到达目的网段。

**详细解释：**

**DUAL（Diffusing Update Algorithm，扩散更新算法）** 是 EIGRP 的核心算法，负责在复杂网络中计算出**最优且无环**的路径。

**几个关键概念：**

| 概念 | 全称 | 含义 |
| :--- | :--- | :--- |
| **FD** | Feasible Distance（可行距离） | 本地到目的网络的**最佳路径度量值** |
| **AD** | Advertised Distance（通告距离） | 邻居到同一目的网络的度量值 |
| **SC** | Successor（后继路由器） | **主用下一跳**路由器 |
| **FS** | Feasible Successor（可行后继） | **备用下一跳**路由器 |
| **FC** | Feasibility Condition（可行性条件） | 确保路径无环的条件，即 **AD < FD** |

**FD 与 AD 的关系：**
> **FD = 本地到邻居的开销 + AD**

**DUAL 的工作逻辑：**
1. 从拓扑表中找出 FD 最小的路径，对应的下一跳就是**后继路由器（SC）**，装入路由表
2. 同时检查有没有满足 **FC（AD < FD）** 的备用路径，如果有，对应的下一跳就是**可行后继（FS）**
3. 当主路径失效时，如果存在 FS，可以**立即切换**，不需要重新计算，这就是 EIGRP 快速收敛的关键
4. 如果没有 FS，才进入 **Active 状态**，向邻居发送 Query 查询，等待 Reply 回复

**与 OSPF 的对比：**
- OSPF 用 **SPF（最短路径优先）** 算法
- EIGRP 用 **DUAL** 算法
- 两者目标类似（最优无环路径），但实现方式不同。DUAL 通过 FC 条件从算法层面**天然防环**，而 OSPF 依靠链路状态数据库的全网同步来保证无环。

**验证命令：**
```
show ip eigrp topology
show ip eigrp topology all-links
```

## 四、协议无关模块（PDM）

**图中原文：** EIGRP 支持 IP、IPv6、AppleTalk 和 IPX，其都有独立 EIGRP 模块，负责处理网络层协议而异的需求。

**详细解释：**

**PDM（Protocol Dependent Module，协议相关模块/协议无关模块）** 是 EIGRP 的模块化设计，让 EIGRP 能够**同时支持多种网络层协议**。

**核心思想：**
- EIGRP 的**核心机制**（邻居发现、RTP、DUAL）是通用的，不依赖于具体承载什么网络层协议
- 但不同网络层协议（IPv4、IPv6、AppleTalk、IPX）的**地址格式、报文封装**不同，所以需要各自的 PDM 模块来处理这些差异
- 每个 PDM 有**独立的邻居表、拓扑表、路由表**

**支持的协议：**
| 协议            | 现状 |
| :------------ | :--- |
| **IPv4**            | 现网主流，必须掌握 |
| **IPv6**            | 现网主流，必须掌握 |
| **AppleTalk**  | 已淘汰，了解即可 |
| **IPX**             | 已淘汰，了解即可 |

**实际应用：**
现网只需要关注 **IPv4 和 IPv6** 的支持。在 Cisco 设备上，配置 IPv4 的 EIGRP 用 `router eigrp <AS号>`，配置 IPv6 的 EIGRP 用 `ipv6 router eigrp <AS号>`，两者是独立的进程和独立的表。

## 四大技术之间的关系

这四项不是孤立的，而是**协同工作**的：

1. **邻居发现协议** → 先找到邻居，建立邻居表
2. **RTP** → 保证路由信息可靠、有序地传给邻居
3. **DUAL** → 拿到路由信息后，计算最优无环路径
4. **PDM** → 让以上机制能适配不同的网络层协议

用一句话串起来：**邻居发现负责“找人”，RTP 负责“可靠传话”，DUAL 负责“算最优路”，PDM 负责“适配多种协议”。** 四者配合，才实现了 EIGRP 快速收敛、无环、可靠的核心优势。
