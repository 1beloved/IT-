**SIA (Stuck-in-Active) 是 EIGRP 中一种特殊的故障状态。** 当路由器针对某条路由发出查询（Query）后，在默认 **3 分钟** 内未收到所有邻居的回复（Reply），该路由就会陷入 SIA 状态，路由器随后会重置未回复邻居的邻接关系以强制收敛

### 核心机制：SIA 如何产生

EIGRP 使用 DUAL 算法。当一条路由的**后继失效**且**没有可行后继**时，该路由会从 **Passive（被动）** 变为 **Active（活动）**。路由器会向所有邻居发送 Query，寻求替代路径

每个处于活动状态的路由都会启动一个 **Active 计时器（默认 180 秒）**。如果在这段时间内未收到全部 Reply，就会触发 SIA。

### SIA 的后续处理流程

以经典场景为例：R1 发 Query 给 R2，R2 需要先问 R3 才能回复 R1，但 R3 出问题不回复。

1. **R2 卡住**：R2 等不到 R3 的 Reply，就无法回复 R1，R2 上的这条路由也进入 Active 状态，时间持续累积
    
2. **SIA 计时器到期**：R1 的 3 分钟计时器先到，R1 认定 R2 陷入 SIA，立刻**重置与 R2 的邻接关系**
    
3. **连锁反应**：R2 收到邻接重置后，也会清除与 R3 的关系，并最终向 R1 回复“不可达”。R1 收到后清除该路由，网络重新收敛
    

### 新旧机制的差异

这直接关系到故障定位的难易程度：

- **旧机制（无 SIA-Query）**：R1 傻等 3 分钟。由于计时器同时启动，路径上**任何**卡住的路由器都可能先超时，导致 SIA 可能被远离故障点的路由器（如 R1）宣告，难以定位根因
    
- **新机制（SIA-Query/SIA-Reply）**：在 Active 计时器过半（**约 90 秒**）时，路由器会发送 **SIA-Query** 探查。如果邻居还在等下游回复，它会回一个 **SIA-Reply**，告知“我还活着，正在等”，从而**重置 SIA 计时器。这使得 SIA 通常只在**真正出问题的那一跳**附近被宣告，大大缩小了排查范围
