**不发送/不接收 EIGRP Hello，但接口所在网段仍然可以参与 EIGRP 路由计算。**

```
R2(config)# router eigrp 100
R2(config-router)# passive-interface g0/1
```


这样做的好处：
- 防止不必要的 Hello
- 防止终端侧建立非预期的 EIGRP 邻居
- 减少协议报文
- 提高安全性
- 网络设计更加清晰


大型网络更常见的思路是：

> **默认所有接口都是 passive，然后只把真正需要建立邻居的接口取消 passive。**

配置：

```
router eigrp 100
 passive-interface default
```

此时：

```
所有接口
   ↓
默认 Passive
```

然后指定真正的 EIGRP 邻居接口：

```
no passive-interface g0/0
no passive-interface g0/1
```


# 一个容易混淆的地方

假设：

```
router eigrp 100
 passive-interface default
```

然后：

```
no passive-interface g0/0
```

**并不意味着 G0/0 一定会建立邻居。**

它只是：

> **允许 EIGRP 在 G0/0 上发送/接收 Hello。**

还必须满足其他 EIGRP 邻居建立条件，例如：

```
AS号一致
K值一致
同一子网
接口未关闭
认证参数一致（如果启用认证）
```

所以：

```
no passive-interface
        ↓
允许建立邻居
        ↓
并不保证一定建立邻居
```

这个逻辑要分清。
